II. BACKGROUND AND RELATED WORKS

A. MODELING ENTERPRISE INSIDER THREATS UNDER AI-NATIVE ORGANIZATIONAL CONSTRAINTS

An insider threat is an action that uses a current or former member's authorized organizational access, knowledge, or trusted relationship to violate a security, privacy, or operational boundary (CISA, 2020; Homoliak et al., 2019). This definition is deliberately broader than “anomalous activity by an employee.” A repository read, a cross-team request, or a model invocation can be normal in one project and harmful in another. The relevant decision depends on the principal, resource, operation, task purpose, recipient, approval path, and validity interval. AI-native enterprise work adds another execution principal. A human employee can initiate a task, a planner can decompose it, a service Agent can retrieve or transform data, and a tool Agent can issue the final API call. An audit record that retains only the employee account therefore cannot establish who authorized an action, who executed it, which source influenced it, or whether the resulting data flow remained within the approved purpose.

Our 15 concrete threat specifications, grouped into three threat families, model this problem as an organizationally constrained information-flow process. The organization is a typed graph containing employees, departments, projects, resources, tools, enterprise Agents, runtimes, and recipients. Reporting, ownership, dependency, visibility, approval, and delegation are explicit edges. A security-relevant event carries human principal, Agent identity, runtime and session, source provenance, task purpose, plan and handoff, effective permission scope, tool invocation, result, recipient, policy decision, and downstream state change. This choice combines attribute-based access control, in which authorization depends on subject, object, action, environment, and policy attributes (NIST SP 800-162), with Zero Trust's requirement to evaluate each access request in its current context (NIST SP 800-207). Purpose restrictions add a further condition. A source object may be legitimately read for one project while a derived summary is illegitimate when sent to a different recipient or model endpoint (Tschantz, Datta, and Wing, 2012). Decentralized label models provide a complementary information-flow view in which data carries restrictions across principals and derived outputs, but they do not specify Agent runtimes or enterprise behavior traces (Myers and Liskov, 2000). OAuth token exchange provides a practical analogue for representing a delegated subject and an actor with a bounded token scope (Jones et al., 2020).

This representation also separates four roles that are routinely collapsed in conventional insider-threat telemetry. The source is the document, message, retrieval result, memory item, or upstream Agent output that enters a context. The human principal initiates, approves, or requests work. The Agent executor plans, delegates, retrieves, or calls tools under a runtime identity. The effect is the changed resource or information-flow edge. An external prompt or malicious document can be recorded as a source, but the trace receives an insider-threat label only when the harmful effect depends on enterprise authority, organizational information, or an enterprise execution chain. This prevents prompt injection and insider misuse from being conflated while still allowing a source to cause an insider violation through an authorized Agent.

A.1. AI-mediated data-boundary abuse

The first threat family, AI-mediated data-boundary abuse, models a boundary violation in which source access is individually legitimate but the generated output crosses an unauthorized boundary. The sequence has four controlled stages. First, an employee reads a task-relevant object under a valid role, department, project, and data-classification decision. Second, the employee or a planner creates a bounded human-to-Agent handoff. The handoff records the Agent identity, runtime, delegated token scope, source objects, recipient policy, and approval state. Third, the Agent retrieves, summarizes, translates, combines, or extracts data, retaining source-to-context-to-tool-to-output lineage. Fourth, the employee or Agent sends or stores the derived artifact at an external endpoint, weaker authorization context, or recipient outside the task purpose. The scenario does not require credential theft, malware, or an access-control exploit. Its security signal is the mismatch between a valid source read and an invalid composed data flow.

This scenario is grounded in several related lines of work. CISA guidance and insider-threat taxonomies establish authorized access and trusted knowledge as the baseline, but their human- and account-oriented abstractions do not distinguish the person requesting a transformation from the Agent executing the output action (CISA, 2020; Homoliak et al., 2019). NIST ABAC and Zero Trust supply subject, resource, environment, and continuous-policy dimensions, but they do not prescribe a provenance record for model context or a derived artifact (NIST, 2019; NIST, 2020). Purpose-restriction research provides the formal intuition that an allowed read does not imply unrestricted downstream use (Tschantz, Datta, and Wing, 2012). MITRE ATT&CK connects valid accounts, repository collection, and web-service exfiltration through T1078, T1213, and T1567, but these techniques identify account activity rather than a human-to-Agent delegation chain. Indirect-prompt-injection work and AgentDojo make the source-to-context-to-tool path observable in LLM applications (Greshake et al., 2023; Debenedetti et al., 2024). NIST AI 600-1 and OWASP's agentic taxonomy further identify data privacy, identity and privilege abuse, tool misuse, and memory or context poisoning as AI-system risks, but they do not instantiate an enterprise department, project-purpose, and recipient graph for insider-threat detection.

The modeling limitation is consequently precise. Existing access-control and Agent-security work can say that an individual read, model call, or send action is permitted or unsafe, yet it rarely preserves the causal evidence needed to decide whether a permitted source was transformed and disclosed for the same organizational purpose. The research question for this scenario is whether a provenance-bearing trajectory can distinguish benign AI-assisted work from a data-boundary violation when source access and most local tool calls are identical, and whether changing only the endpoint, recipient, or delegated scope yields a local and explainable detection change.

A.2. Cross-department workflow abuse

The second threat family, cross-department workflow abuse, models a distributed violation whose evidence is split across departments and workdays. The employee enters a legitimate project, handoff, or temporary coverage activity. The employee and cooperating Agents then request small fragments from several departments through ordinary communication and approval channels. A coordination Agent aggregates or stages the fragments while preserving source department, ownership, purpose, approval chain, Agent identity, handoff messages, and artifact lineage. The combined artifact is finally routed to a recipient or downstream task outside the original dependency path, after an approval or temporary delegation has expired, or for a purpose that did not authorize the complete information set. Each request can pass a local permission check even though the composed information flow is unauthorized.

The related-work foundation is workflow- and relationship-aware authorization. ABAC and Zero Trust make department, role, resource, and environment attributes policy inputs (NIST, 2019; NIST, 2020). Classical workflow authorization research shows why ordinary RBAC is insufficient when separation-of-duty and dynamic task constraints span multiple activities (Bertino, Ferrari, and Atluri, 1999). OAuth token exchange and purpose-bound capability proposals make delegated authority explicit and attenuated (Jones et al., 2020; Tran-Truong et al., 2026; Muruaga, 2026). MITRE's valid-account and repository-collection techniques cover trusted access and information gathering. Facade shows that high-precision detection benefits from jointly modeling users and enterprise resources across document, SQL, and HTTP/RPC logs (Kantchelian et al., 2026). Selling the Dream demonstrates that identity relationships and visibility can change insider risk even in small organizations (Sabri et al., 2026). OrgAccess evaluates role-based permission decisions for organization-scale LLM requests, including requests with multiple simultaneous constraints (Sanyal et al., 2026). These works establish that a single account or isolated request is an insufficient unit of analysis. They do not, however, provide a paired long-horizon trajectory in which department ownership, dependency paths, approval expiry, inter-Agent messages, and aggregate artifact lineage are jointly controlled.

The limitation maps directly to our question. Existing authorization and detection methods can validate the component request but may not reconstruct why the components were combined, which business purpose authorized the combination, or which principal is responsible for the final artifact. We therefore ask whether organization-aware provenance can identify a distributed threat when every individual request is plausible, and whether changing one dependency edge, temporary delegation, approval scope, or Agent handoff produces a verifiable change in downstream state.

A.3. Skill and memory contamination

The third threat family, skill and memory contamination, models persistent state as an organizational security boundary. A skill or memory item that was valid for an earlier task may become unsafe when the current employee, department, resource scope, recipient, project purpose, or approval window changes. The scenario first stores a procedure with incomplete provenance or an overbroad scope. A semantically similar later task retrieves it. The human-planner to tool-Agent handoff inserts the procedure without checking origin scope, current role, preconditions, expiry, memory tenancy, or permission scope. The tool Agent then performs an unauthorized read, transfer, or modification. The resulting memory may be written to a shared namespace or propagated to another employee or Agent, increasing duration and attribution difficulty.

Agent-memory research establishes the capability side of this problem. ProcMEM, MACLA, LEGOMem, SAGE, and related skill-library work extract, select, or compose procedures to improve long-horizon task reuse (Mi et al., 2026; Forouzandeh et al., 2026; Han et al., 2026; Wang et al., 2026). From Memory to Skills argues that evidence links, applicability boundaries, verification rules, and reliability estimates should govern the conversion of experience into reusable skills (Tang et al., 2026). The security side is visible in OWASP's memory and context poisoning category and in Liu et al.'s study of 98,380 third-party skills, which identified 157 malicious skills in the wild (OWASP, 2026; Liu et al., 2026). MATE makes policy-aware trajectory auditing concrete, while Context Contamination shows that passive prompt injection can manipulate the context used for security-log analysis (Jiang et al., 2026; Karanjai et al., 2026). These results establish that persistent memory is both a source of capability and an attack surface.

Their remaining limitation is organizational. Skill and memory systems generally optimize task success, retrieval quality, transfer, or supply-chain screening. They do not make origin role, source department, permission scope, recipient, tenant, approval window, and expiry jointly executable conditions for tool use. A malicious skill can be detected as unsafe in isolation while a stale but originally benign skill remains undetected when it silently expands the current employee's reachable actions. Our research question is whether provenance-constrained retrieval and execution can prevent unauthorized reuse without eliminating useful reuse, and whether a single change to skill provenance, scope, expiry, tenancy, or current role produces a localized and attributable trajectory change.

The 15 scenarios use the same experimental philosophy. A benign trajectory and a threat trajectory begin from the same organization graph, employee profiles and roles, schedule and task goal, initial permissions, tool state, and, where supported, model configuration and random seed. The generator changes one intervention only. For data-boundary abuse the intervention can be the model endpoint, recipient, or delegated scope. For cross-department abuse it can be a dependency path, approval scope, temporary delegation, or handoff. For skill contamination it can be provenance, scope, expiry, tenancy, or current-role context. The resulting traces retain typed null events and provenance so that inserted, skipped, or rerouted actions remain comparable. This design treats an insider threat as an organizationally constrained counterfactual, rather than as a manually written attack story.

This construction addresses a limitation shared by conventional insider-threat models. Account-centered labels can identify who touched an object, but cannot establish whether the action preserved task purpose, whether the Agent was acting under a valid delegation, whether a derived artifact inherited source restrictions, or whether a reused skill was still valid. The central question carried into the rest of the paper is therefore whether an enterprise Agent harness can generate and audit provenance-bearing organizational trajectories that make these distinctions measurable.

B. AGENT HARNESSES ACROSS DOMAINS AND THE BOUNDARY OF CHIMERA

Agent harnesses have developed from message-passing demonstrations into stateful environments that expose tools, long-horizon tasks, policies, communication protocols, and persistent memory. The progression matters for this work because each domain makes a different part of an Agent trajectory observable, while no single benchmark supplies the full organizational security state required by these 15 scenarios.

B.1. General multi-Agent collaboration and enterprise tasks

CAMEL, AutoGen, and MetaGPT established reusable coordination patterns based on role assignment, conversation, task decomposition, and software-engineering artifacts (Li et al., 2023; Wu et al., 2024; Hong et al., 2024). TheAgentCompany moves toward enterprise work by placing Agents in a simulated software company with internal websites, code, tasks, and coworker communication (Xu et al., 2025). These frameworks demonstrate that role-specialized Agents and structured collaboration can produce multi-step work that is richer than a single prompt-response exchange. The unit of evaluation remains mainly task completion, dialogue quality, or tool success. A human initiator, Agent runtime identity, delegated authority, project purpose, and downstream state are not consistently first-class audit objects.

For our research question, the limitation is not that these frameworks lack roles or organizational language. Their trajectories do not generally test whether the same tool call is authorized under two different delegation scopes, project purposes, or department dependencies. They therefore cannot by themselves generate a benign/threat pair for an AI-mediated insider violation.

B.2. Web, desktop, and task-generation harnesses

AgentBench evaluates LLM Agents across multiple environments and task types, WebArena provides realistic websites and stateful Web interaction, and OSWorld evaluates open-ended multimodal computer use (Liu et al., 2023; Zhou et al., 2024; Xie et al., 2024). TheAgentCompany adds internal enterprise applications, while ST-WebAgentBench evaluates safety and trustworthiness under explicit Web policies and OrgAccess evaluates role-based access decisions for organization-scale LLM requests (Levy et al., 2026; Sanyal et al., 2026). AgentSynth, APIGen-MT, TaskCraft, WebGym, and WebSTAR scale task blueprints, simulated human-Agent interaction, exploration, and step-level filtering for long executable trajectories (Xie et al., 2026; Prabhakar et al., 2025; Shi et al., 2026; Bai et al., 2026; He et al., 2026). Together, these systems cover software engineering, browsing, desktop operation, mobile interaction, simulated enterprise work, and synthetic task generation. Their task domains also span email, banking, and travel workflows in AgentDojo and travel, healthcare, and finance protocol scenarios in A2ASecBench, showing that Agent-harnesses are being adapted to application-specific policies rather than a single benchmark world (Debenedetti et al., 2024; Li et al., 2026). Agent simulation has also moved into news recommendation, mixed-autonomy traffic, and social interaction. LLMEvalRec reports strong agreement with real recommendation rankings, UrbanMix uses bounded LLM planning in SUMO traffic networks, and Generative Agents studies memory-supported social behavior (Ma et al., 2026; Sultimov et al., 2026; Park et al., 2023). These domain-specific roles and bounded actions do not encode enterprise purpose, delegation, or insider accountability.

Their common abstraction is a task, policy query, or completed action. Permissions are often checked at one action or task boundary. Department ownership, approval validity, cross-department information flow, source-to-context-to-plan causality, and persistent skill tenancy are usually outside the state transition. These harnesses can reveal whether an Agent completes a workflow or violates an explicit policy, but they do not show whether a locally valid sequence becomes invalid when its organizational purpose and delegation history are reconstructed. This is the limitation relevant to our research question.

B.3. Agent security, multi-Agent protocols, and causal auditing

Security benchmarks add adversarial sources and policy-sensitive trajectories. Greshake et al. demonstrate indirect prompt injection against LLM-integrated applications, and AgentDojo evaluates prompt-injection attacks and defenses in a dynamic tool-use environment (Greshake et al., 2023; Debenedetti et al., 2024). AgentLAB targets long-horizon attacks such as objective drifting, tool chaining, task injection, and memory poisoning (Jiang et al., 2026). MATE binds synthetic mobile trajectories to natural-language policies for security auditing. Architecture Matters for Multi-Agent Security studies how role assignment, communication topology, and memory visibility alter attack surfaces. A2ASecBench places protocol attacks involving capability discovery, task orchestration, and artifact exchange in Agent-to-Agent workflows. CausalTrace uses sequential structure and intervention-oriented reasoning for multi-step Agent attacks (Mothukuri and Parizi, 2026; Hagag et al., 2026; Li et al., 2026). DelegateGuard and Bounded Agents formalize purpose-bound delegation, attenuation, and revocation for delegated Agents (Tran-Truong et al., 2026; Muruaga, 2026).

This line of work makes source influence, tool use, communication, protocol state, and long-horizon attack effects more visible. Its limitation for our problem is that organization-constrained insider threats are not normally the principal variable. A valid employee identity, an expired approval, a cross-department business purpose, and an Agent executor must be combined with an effect witness. Security benchmarks often ask whether an Agent is hijacked or whether a protocol is violated, while our question asks whether the same enterprise workflow remains within the authorized organizational purpose after a single intervention.

B.4. Persistent procedural memory and skills

Procedural-memory harnesses improve reuse by extracting or composing reusable experience. ProcMEM learns reusable procedures, MACLA learns hierarchical procedural memory, LEGOMem organizes modular procedures for multi-Agent systems, and SAGE and skill-library methods study self-improvement through stored workflows. From Memory to Skills adds evidence grounding and applicability checks to the memory-to-skill conversion (Tang et al., 2026; Wang et al., 2026). Liu et al.'s empirical study of malicious Agent skills shows that an external skill ecosystem can also become a supply-chain attack surface (Liu et al., 2026).

These systems explain why memory can make an Agent both more capable and more persistent. Their main evaluation questions concern utility, retrieval, transfer, or whether a skill is malicious. They do not usually evaluate a skill's origin department, current employee, permission scope, memory tenant, recipient restriction, or expiry as a causal intervention. The resulting limitation is exactly the third scenario's question: can an Agent reuse an old procedure only when the current organization state still authorizes it, and can a detector attribute a later tool action to the contaminated retrieval path?

B.5. What Chimera provides and what it cannot model

Chimera is an important predecessor rather than a framework without organizational structure. It provides organization profiles, role- and personality-conditioned employee Agents, meetings and schedules, normal and malicious behavior, multi-stage attack specifications, and six application- and system-level log modalities (Yu et al., 2026). Its ChimeraLog enables comparisons across technology, finance, and medical organizations, and its experiments show that conventional ITD methods degrade under distribution shift. These capabilities establish a strong basis for enterprise-scale synthetic behavior generation.

The boundary is the security state controlled by the attack specification. Chimera does not consistently expose an Agent identity and runtime as a first-class principal tied to every tool event. It does not maintain a complete human-to-Agent delegation and approval chain, source and model-context provenance, cross-department purpose restriction, skill or memory origin and expiry, or attribution of a downstream state change to the human initiator, Agent executor, source, and affected resource. Its benign and attack traces are not defined as replays from one fixed organization snapshot in which one authorization, recipient, dependency, or memory variable is changed while the rest of the state is held fixed. Chimera therefore models organizational activity and multi-Agent behavior, but it cannot fully model the AI-native organizational constraints that define these 15 scenarios.

The research problem is specific. An extension must retain Chimera's multi-domain, long-horizon, multimodal behavior while turning Agent identity, delegation, purpose, source provenance, skill scope, and downstream effects into executable state. Paired benign and threat trajectories can then expose the effect of each organizational intervention for detection, attribution, and audit.

C. INSIDER-THREAT DATASETS AND DETECTION METHODS

C.1. Datasets and data-generation systems

CERT remains the most common reproducible insider-threat benchmark. It provides background activity, scripted malicious scenarios, answer files, and application-level log modalities including logon, email, device, HTTP, file, and psychometric activity (CMU SEI, 2020). Its strength is controlled labels and repeatability. Its synthetic users, scenario scripts, user-day-oriented labels, and limited business semantics make it difficult to represent a valid read followed by an unauthorized Agent-mediated transformation. CERT has no native Agent identity, delegation chain, model context, skill provenance, or downstream service-state witness.

TWOS uses human participants in a gamified red-team and blue-team setting and therefore provides more natural malicious behavior than a fully scripted generator (Harilal et al., 2017). The trade-off is limited scale, coverage, and repeatability. LANL's Cyber1 data provides real authentication, process, and network events but lacks application semantics and complete threat labels, while the Enron corpus provides real enterprise communication (Los Alamos National Laboratory, 2015; Enron, 2004). Neither corpus jointly provides organizational purpose, complete authorization paths, insider ground truth, Agent traces, tool results, and downstream harm. These datasets are valuable behavior anchors but cannot serve as ground-truth AI-native enterprise trajectories.

ChimeraLog expands synthetic generation to multiple organizations, foundation models, application logs, and system telemetry. Its reported distribution-shift experiments are important evidence that a detector with a strong CERT result can degrade substantially on a new organization. For example, the DS-IID F1 reported in the Chimera study is 0.955 for CERT-to-CERT, 0.464 for CERT-to-Chimera-Finance, and 0.739 in the reverse direction (Yu et al., 2026). The result demonstrates the need for cross-organization evaluation, but the attack specification remains the primary intervention surface. The logs do not consistently encode the organizational authorization, human-to-Agent handoff, source lineage, or skill validity that determine the three new threat families.

OrgForge-IT uses a deterministic state engine, natural-language materials, independent ground truth, and clean baselines to separate triage, attribution, and harm (Flynt, 2026). Its reported corpus contains 51 days, four detection scenarios, 2,904 telemetry records, 106 signals, and 2,798 noise records. This makes label verification and responsibility analysis more explicit than in many prior datasets. Its scenario coverage remains limited, and its cross-organization validity and coverage of human-Agent handoff, cross-department purpose, and skill contamination require independent evaluation.

MOLE studies monitoring of AI-operated accounts in stateful services and verifies whether an account-day caused actual service damage (Muhamed and Smith, 2026). The benchmark contains 150 AI-operated accounts, six teams, nine services, and 30 workdays. In a cross-generator comparison, it matches the account, role, date, harmful objective, and target repository, while earlier account activity and service state remain corpus-specific. Its emphasis is AI-account monitoring in one synthetic organization with fixed roles, services, and assigned threats. Delegation validity, cross-department business purpose, source provenance, and skill origin are not its primary intervention variables. Matching account, role, date, objective, and target therefore does not answer whether a human initiated the action, which Agent executed it, or whether a reused skill expanded its authorized scope.

The dataset limitation is thus not simply that public traces are synthetic. Real corpora lack semantics and labels, controlled corpora simplify organization state, and current Agent corpora expose only part of the causal chain. None of the common benchmarks simultaneously provides a fixed organization snapshot, a single controlled authorization or memory intervention, complete source-to-executor provenance, and a verified downstream effect. Our dataset question is whether a trajectory generator can add these fields while remaining behaviorally useful for existing detection tasks and cross-organization transfer.

C.2. Detection methods

Traditional rules and user-and-entity behavior analytics establish the operational baseline by learning thresholds, peer-group deviations, access sequences, and risk scores. Machine-learning methods use SVMs, CNNs, autoencoders, graph neural networks, and temporal models over user, session, or user-day features. ISFL-AE conditions an autoencoder on insider-specific attributes such as role and permission (Kim and Kim, 2026). The dual-graph GCN and Bi-LSTM method combines explicit and learned employee-resource graphs with temporal dependencies (Yumlembam et al., 2026). These methods demonstrate that role, resource relations, and time improve anomaly detection, but the prediction unit remains a behavior window or account-linked activity.

Recent approaches incorporate language models and cross-source reasoning. Facade jointly models users and enterprise resources over document, SQL, and HTTP/RPC logs and targets high-precision contextual anomaly detection. In its deployment study, the reported false-positive rate is below 0.01% for the audited event stream, illustrating the value of contextual filtering under a low-FPR budget (Kantchelian et al., 2026). Insight-LLM fuses text, sentiment, temporal, and graph views with pretrained encoders and reports F1 values of 0.9712 on CERT r4.2 and 0.9594 on CERT r5.2 (Song et al., 2026). LLMBA learns temporal and contextual behavior representations for zero-trust networks (Yan et al., 2026a, 2026b). MARS-ITD separates parallel anomaly screening from cross-log collaborative investigation and reports 94.44% recall, 95.42% accuracy, and 4.58% FPR on CERT r4.2 (Cheng et al., 2026), while Audit-LLM uses multiple roles to query and cross-check evidence (Song et al., 2024). These methods move from isolated events toward multi-view evidence and investigation workflows.

Their shared limitation is the semantic target. Most systems decide whether a user, account, session, or user-day is anomalous or risky. An anomaly score does not necessarily determine whether a business purpose was violated, whether a delegation was expired, which Agent issued the action, or whether a source and derived output crossed a forbidden boundary. Few methods jointly distinguish the human initiator, Agent executor, runtime identity, delegation chain, source input, skill or memory provenance, affected resource, and final recipient. Most are also evaluated within a fixed data distribution. The Chimera results show that cross-organization performance can decline sharply, and the same issue can arise when departments, tools, model providers, or memory policies change.

The metrics further limit interpretation. Accuracy, F1, AUC, and even PR-AUC do not by themselves report low-FPR recall under an investigation budget, responsibility attribution, detection delay, downstream harm, or whether the alert changed only because of the intended intervention. OrgForge-IT and MOLE begin to separate triage, attribution, verified harm, and review-budget recall, but they do not cover the full AI-native organizational state. A detector trained on conventional logs can therefore appear successful while learning account or scenario artifacts instead of the authorization and provenance relation that defines the threat.

The detection question for this work follows directly. Taking the same workflow and fixed false-positive budget, does adding organization, task-purpose, delegation, source, Agent-runtime, skill, recipient, and downstream-state evidence improve violation detection, responsibility attribution, and harm identification? The evaluation unit must be a provenance-bearing organizational trajectory rather than only a user-day or account-day. Detection metrics should include low-FPR recall, PR-AUC, calibration, event- and session-level delay, attribution error, unauthorized-action rate, and cross-organization transfer, alongside explicit checks of authorization-chain completeness and counterfactual trajectory locality.

II. 背景与相关工作

A. AI 原生组织约束下的企业内部威胁建模

内部威胁是指当前或曾经拥有组织资源、组织知识或可信关系的成员，利用组织授权越过安全、隐私或运营边界而采取的行动（CISA，2020；Homoliak 等，2019）。这个定义比“员工的异常活动”更宽。员工读取代码仓库、跨团队请求资料或调用模型，在一个项目中可能完全正常，在另一个项目中却可能造成危害。判断依据包括主体、资源、操作、任务目的、接收者、审批路径和有效时间。AI 原生企业工作还引入了新的执行主体。员工可以发起任务，规划 Agent 可以拆解任务，服务 Agent 可以检索或转换数据，工具 Agent 可以发出最终 API 调用。因此，只保留员工账号的审计记录无法确定谁授权了动作、谁执行了动作、哪些来源影响了动作，以及最终数据流是否仍属于获批目的。

我们的 15 个具体威胁规格按三个威胁族组织，共同把这个问题建模为受组织约束的信息流过程。组织是一个类型化图，包含员工、部门、项目、资源、工具、企业 Agent、运行时和接收者。汇报、所有权、依赖、可见性、审批和委托都表示为显式边。安全相关事件包含人类主体、Agent 身份、运行时和会话、来源溯源、任务目的、计划和交接、有效权限范围、工具调用、结果、接收者、策略决策和下游状态变化。这个选择结合了基于属性的访问控制和零信任架构。前者要求授权依赖主体、对象、动作、环境和策略属性（NIST SP 800-162），后者要求在当前上下文中持续评估每次访问请求（NIST SP 800-207）。目的限制还增加了一个条件。某个源对象可以因为一个项目而被合法读取，但由它生成的摘要发给另一个接收者或模型端点时可能已经越过项目目的（Tschantz、Datta 和 Wing，2012）。去中心化标签模型从信息流角度补充了这一点。数据可以在主体之间传播时携带限制，派生输出也应继承这些限制，但该模型没有规定 Agent 运行时或企业行为轨迹（Myers 和 Liskov，2000）。OAuth 令牌交换为表示受限的被委托主体和执行者提供了实践上的类比（Jones 等，2020）。

这一表示还把传统内部威胁遥测中经常混在一起的四种角色分开。来源是进入上下文的文档、消息、检索结果、记忆项或上游 Agent 输出。人类主体发起、批准或请求工作。Agent 执行者在特定运行时身份下规划、委托、检索或调用工具。效果是发生状态变化的资源或信息流边。外部提示或恶意文档可以作为来源记录，但只有当危害依赖企业授权、组织信息或企业执行链时，该轨迹才标为内部威胁。这样既不会把提示注入与内部滥用混为一谈，也允许记录一个来源通过获授权 Agent 造成内部违规的情况。

A.1 AI 中介的数据边界滥用

第一类威胁，即 AI 中介的数据边界滥用 建模这样一种边界违规：源数据的访问本身合法，但生成的结果越过了未获授权的边界。过程包含四个可控阶段。第一，员工在有效岗位、部门、项目和数据分类决策下读取任务相关对象。第二，员工或规划器创建受限的人到 Agent 交接。交接记录 Agent 身份、运行时、委托令牌范围、源对象、接收者策略和审批状态。第三，Agent 检索、摘要、翻译、合并或提取数据，并保留源到上下文、工具再到输出的谱系。第四，员工或 Agent 将派生工件发送或存储到外部端点、较弱授权上下文或项目目的之外的接收者。场景不要求凭证窃取、恶意软件或访问控制漏洞。安全信号来自合法源读取与非法组合数据流之间的不匹配。

相关工作来自几条研究路线。CISA 指南和内部威胁分类学以授权访问和可信知识为基线，但面向人和账号的抽象没有区分请求转换的人员与执行输出动作的 Agent（CISA，2020；Homoliak 等，2019）。NIST ABAC 和零信任提供主体、资源、环境和持续策略维度，却没有规定模型上下文或派生工件的溯源记录（NIST，2019；NIST，2020）。目的限制研究形式化了一个重要直觉，即被允许读取不等于可以不受限制地使用下游数据（Tschantz、Datta 和 Wing，2012）。MITRE ATT&CK 通过 T1078、T1213 和 T1567 把有效账号、仓库收集和 Web 服务外泄连接起来，但这些技术描述的是账号活动，而不是人到 Agent 的委托链。间接提示注入研究和 AgentDojo 让来源到上下文再到工具的路径变得可观察（Greshake 等，2023；Debenedetti 等，2024）。NIST AI 600-1 和 OWASP Agentic 风险分类还指出数据隐私、身份和权限滥用、工具误用以及记忆或上下文污染风险，但没有为内部威胁检测建立企业部门、项目目的和接收者图。

因此，现有访问控制和 Agent 安全工作留下了一个明确局限。它们可以判断一次读取、模型调用或发送动作是否被允许或不安全，却很少保留判断“被允许的源数据是否被转换后用于同一组织目的”所需要的因果证据。本场景对应的研究问题是：当源访问和大多数局部工具调用相同时，带溯源的轨迹能否区分正常的 AI 辅助工作与数据边界违规；只改变端点、接收者或委托范围，是否会带来局部且可解释的检测变化。

A.2 跨部门工作流滥用

第二类威胁，即跨部门工作流滥用 建模一种跨部门、跨工作日分散出现的违规。员工先进入合法项目、交接或临时代班活动。随后，员工和合作 Agent 通过正常沟通与审批渠道，从多个部门请求少量信息。协调 Agent 聚合或暂存这些片段，同时保留来源部门、所有权、目的、审批链、Agent 身份、交接消息和工件谱系。最终，组合工件被路由到原依赖路径之外的接收者或下游任务，也可能发生在临时授权已过期之后，或被用于没有授权完整信息集的目的。每个请求都可以通过局部权限检查，但组合后的信息流仍然未经授权。

相关工作的基础是工作流和关系感知授权。ABAC 与零信任把部门、岗位、资源和环境属性纳入策略（NIST，2019；NIST，2020）。经典工作流授权研究说明，当分离职责和动态任务约束跨越多个活动时，普通 RBAC 不足以表达这些约束（Bertino、Ferrari 和 Atluri，1999）。OAuth 令牌交换和目的绑定能力方案使委托权限、权限衰减和撤销变得显式（Jones 等，2020；Tran-Truong 等，2026；Muruaga，2026）。MITRE 的有效账号和仓库收集技术覆盖可信访问和信息收集。Facade 表明，在文档、SQL 以及 HTTP/RPC 日志中联合建模用户和企业资源，有助于高精度检测（Kantchelian 等，2026）。Selling the Dream 表明，身份关系和可见性的变化会改变小型组织中的内部风险（Sabri 等，2026）。OrgAccess 对组织规模 LLM 请求中的基于角色权限决策进行评估，包括同时满足多个约束的请求（Sanyal 等，2026）。这些工作共同说明单账号或孤立请求不是充分分析单位，但它们没有提供一个同时控制部门所有权、依赖路径、审批有效期、跨 Agent 消息和聚合工件谱系的长时程配对轨迹。

这个局限直接对应我们的研究问题。现有授权和检测方法可以验证组成请求，却可能无法还原这些请求为什么被组合、哪个业务目的授权了组合，以及谁应为最终工件负责。因此，我们要研究：当每个单独请求都合理时，组织感知的溯源能否识别分布式威胁；只改变一个依赖边、临时委托、审批范围或 Agent 交接，是否会让下游状态产生可核验变化。

A.3 技能与记忆污染

第三类威胁，即技能与记忆污染 把持久化状态建模为组织安全边界。某个历史任务中有效的技能或记忆，在当前员工、部门、资源范围、接收者、项目目的或审批窗口变化后，可能变得不安全。场景首先把溯源不完整或范围过宽的流程写入记忆。之后，一个语义相似的任务检索该流程。人到 Agent 的交接把它加入计划，却没有检查来源范围、当前岗位、前置条件、有效期、记忆租户或权限范围。工具 Agent 随后执行未授权的读取、传输或修改。结果还可能被写入共享命名空间，传播给另一名员工或另一个 Agent，使影响持续更久，也更难归因。

Agent 记忆研究建立了这个问题的能力基础。ProcMEM、MACLA、LEGOMem、SAGE 以及相关技能库工作通过提取、选择或组合流程，提高长时程任务复用能力（Mi 等，2026；Forouzandeh 等，2026；Han 等，2026；Wang 等，2026）。From Memory to Skills 进一步提出，应以证据链接、适用边界、验证规则和可靠性估计约束从经验到可复用技能的转换（Tang 等，2026）。OWASP 的记忆和上下文污染类别，以及 Liu 等人对 98,380 个第三方技能的研究，说明记忆既是能力来源，也是供应链攻击面，该研究发现了 157 个恶意技能（OWASP，2026；Liu 等，2026）。MATE 将策略感知的轨迹审计具体化，Context Contamination 则表明被动提示注入可以操控安全日志分析所使用的上下文（Jiang 等，2026；Karanjai 等，2026）。这些结果说明持久记忆同时影响能力与安全性。

它们留下的局限是组织性的。技能和记忆系统通常优化任务成功率、检索质量、迁移效果或供应链筛查，很少把来源岗位、来源部门、权限范围、接收者、租户、审批窗口和有效期共同作为工具执行的可执行条件。恶意技能可以在单独检查时被识别，而一个原本善意但已经过期的技能，可能在不被发现的情况下扩张当前员工可触达的动作。本场景对应的研究问题是：带溯源约束的检索和执行能否阻止未授权复用而不消除有用复用；只改变技能来源、范围、有效期、租户或当前岗位，是否会带来局部且可归因的轨迹变化。

15 个场景使用同一实验哲学。良性轨迹和威胁轨迹从相同的组织图、员工档案和岗位、日程与任务目标、初始权限、工具状态，以及在可行时相同的模型配置和随机种子开始。生成器只改变一个干预变量。数据边界场景改变模型端点、接收者或委托范围。跨部门场景改变依赖路径、审批范围、临时委托或交接。技能污染场景改变溯源、范围、有效期、租户或当前岗位上下文。轨迹保留类型化空事件和溯源，使插入、跳过或改道的动作仍然可以比较。这个设计把内部威胁视为受组织约束的反事实，而不是手工书写的攻击故事。

这一构造回应了传统内部威胁模型的共同局限。以账号为中心的标签可以识别谁接触了对象，却无法说明动作是否保留了任务目的、Agent 是否处于有效委托下、派生工件是否继承了源限制、以及被复用技能是否仍然有效。因此，贯穿后续部分的核心问题是：企业 Agent harness 能否生成并审计带来源溯源的组织轨迹，使这些差异变得可测量。

B. 不同领域的 Agent-harness 与 Chimera 的边界

Agent-harness 已经从消息传递演示发展为暴露工具、长时程任务、策略、通信协议和持久记忆的有状态环境。这个发展对本文很重要，因为不同领域让 Agent 轨迹的不同部分变得可观察，但没有任何单一基准提供上述 15 个场景所需的完整组织安全状态。

B.1 通用多 Agent 协作与企业任务

CAMEL、AutoGen 和 MetaGPT 建立了基于角色分配、对话、任务分解和软件工程工件的可复用协作模式（Li 等，2023；Wu 等，2024；Hong 等，2024）。TheAgentCompany 通过在包含内部网站、代码、任务和同事沟通的模拟软件公司中运行 Agent，进一步接近企业工作（Xu 等，2025）。这些框架说明，角色专门化和结构化协作能够产生比单一问答更丰富的多步骤工作。评测单位仍主要是任务完成、对话质量或工具成功率。人类发起者、Agent 运行时身份、委托权限、项目目的和下游状态并没有稳定地成为一等审计对象。

对我们的研究问题而言，局限不在于这些框架没有角色或组织语言。它们通常不测试同一个工具调用在不同委托范围、项目目的或部门依赖下是否仍然被授权。因此，它们无法独立生成 AI 中介内部违规所需的良性和威胁配对轨迹。

B.2 Web、桌面和任务生成 harness

AgentBench 在多种环境和任务类型上评估 LLM Agent，WebArena 提供具有真实感的网站和有状态 Web 交互，OSWorld 评估开放式多模态计算机使用（Liu 等，2023；Zhou 等，2024；Xie 等，2024）。TheAgentCompany 加入内部企业应用，ST-WebAgentBench 在显式 Web 策略下评估安全性和可信度，OrgAccess 评估组织规模 LLM 请求的基于角色的权限决策（Levy 等，2026；Sanyal 等，2026）。AgentSynth、APIGen-MT、TaskCraft、WebGym 和 WebSTAR 扩展任务蓝图、模拟人机交互、探索以及带步骤过滤的长轨迹（Xie 等，2026；Prabhakar 等，2025；Shi 等，2026；Bai 等，2026；He 等，2026）。这些系统已经覆盖软件工程、浏览器、桌面操作、移动交互、模拟企业工作和合成任务生成。它们的任务领域还包括 AgentDojo 中的邮件、银行和旅行工作流，以及 A2ASecBench 中的旅行、医疗和金融协议场景，说明 Agent-harness 正在适应带有领域策略的应用，而不是只服务于单一基准世界（Debenedetti 等，2024；Li 等，2026）。Agent 模拟还扩展到新闻推荐、混合自动驾驶交通和社会互动。LLMEvalRec 报告了与真实推荐排序的较强一致性，UrbanMix 在 SUMO 交通网络中使用受限的 LLM 规划，Generative Agents 研究了依赖记忆的社会行为（Ma 等，2026；Sultimov 等，2026；Park 等，2023）。这些领域特定的角色和有界动作仍然没有编码企业目的、委托或内部威胁责任。

它们的共同抽象是任务、权限查询或完成的动作。权限通常在一次动作或一个任务边界进行检查。部门所有权、审批有效期、跨部门信息流、来源到上下文再到计划的因果关系以及持久技能租户通常不属于状态转移。这些 harness 可以说明 Agent 能否完成工作流或违反显式策略，却不能说明当重建组织目的和委托历史后，一个局部合法的序列是否整体失效。这正是与本文研究问题相关的局限。

B.3 Agent 安全、多 Agent 协议与因果审计

安全基准把对抗性来源和策略敏感轨迹加入评测。Greshake 等人展示了针对 LLM 集成应用的间接提示注入，AgentDojo 在动态工具使用环境中评估提示注入及防御（Greshake 等，2023；Debenedetti 等，2024）。AgentLAB 研究目标漂移、工具链、任务注入和记忆污染等长时程攻击（Jiang 等，2026）。MATE 把合成移动轨迹与自然语言策略绑定用于安全审计。Architecture Matters for Multi-Agent Security 研究角色分配、通信拓扑和记忆可见性如何改变攻击面。A2ASecBench 把能力发现、任务编排和工件交换等协议攻击放入 Agent-to-Agent 工作流。CausalTrace 用顺序结构和面向干预的推理处理多步骤 Agent 攻击（Mothukuri 和 Parizi，2026；Hagag 等，2026；Li 等，2026）。DelegateGuard 和 Bounded Agents 形式化了委托 Agent 的目的绑定、权限衰减和撤销（Tran-Truong 等，2026；Muruaga，2026）。

这条路线让来源影响、工具使用、通信、协议状态和长时程攻击效果变得更可见。对于我们的问题，它的局限是组织约束的内部威胁通常不是主要变量。有效员工身份、过期审批、跨部门业务目的和 Agent 执行者需要与实际效果证据组合起来。安全基准通常询问 Agent 是否被劫持或协议是否违规，而我们的研究询问同一个企业工作流在单一干预之后是否仍然处于获批的组织目的内。

B.4 持久化流程记忆与技能

流程记忆 harness 通过提取或组合可复用经验提高任务复用。ProcMEM 学习可复用流程，MACLA 学习层级程序记忆，LEGOMem 组织多 Agent 系统的模块化流程，SAGE 与技能库方法研究通过存储工作流实现自我改进。From Memory to Skills 为从记忆到技能的转换增加证据约束和适用性检查（Tang 等，2026；Wang 等，2026）。Liu 等人对恶意 Agent 技能的实证研究表明，外部技能生态也可能成为供应链攻击面（Liu 等，2026）。

这些系统说明记忆如何让 Agent 更有能力，也让影响更持久。它们的主要评测关注效用、检索、迁移或技能是否恶意。它们通常不把技能的来源部门、当前员工、权限范围、记忆租户、接收者限制或有效期作为因果干预变量。这一局限正对应第三类威胁的问题：只有当当前组织状态仍然授权时，Agent 是否能够复用旧流程；检测器能否把后续工具动作归因于受污染的检索路径。

B.5 Chimera 已有能力与不能建模的内容

Chimera 是重要前身，并不是一个没有组织结构的框架。它提供组织画像、带岗位和个性的员工 Agent、会议与日程、正常和恶意行为、多阶段攻击规格，以及六种应用层和系统层日志模态（Yu 等，2026）。ChimeraLog 支持在科技、金融和医疗组织之间进行比较，实验还显示传统内部威胁检测方法在分布迁移下会退化。这些能力为企业规模的合成行为生成建立了基础。

其边界在于由攻击规格控制的安全状态。Chimera 没有持续把 Agent 身份和运行时作为一等主体绑定到每个工具事件，也没有完整维护人到 Agent 的委托和审批链、来源与模型上下文溯源、跨部门目的限制、技能或记忆的来源与有效期，或者把下游状态变化归因于人类发起者、Agent 执行者、来源和受影响资源。它的良性轨迹和攻击轨迹也没有被定义为来自同一固定组织快照、只改变一个授权、接收者、依赖关系或记忆变量的重放。因此，Chimera 能建模组织活动和多 Agent 行为，却无法完整建模这 15 个场景所定义的 AI 原生组织约束。

由此得到的研究问题是具体的。在保留 Chimera 的多领域、长时程和多模态行为的同时，应把 Agent 身份、委托、目的、来源溯源、技能范围和下游效果变成可执行状态。随后通过良性和威胁配对轨迹，检测、归因和审计每个组织干预的影响。

C. 内部威胁数据集与检测方法

C.1 数据集与数据生成系统

CERT 仍然是最常用、最可复现的内部威胁基准。它提供背景活动、脚本化恶意场景、答案文件，以及 logon、email、device、HTTP、file 和 psychometric 等应用层日志（CMU SEI，2020）。它的优点是标签受控且可重复。其合成用户、场景脚本、以用户日为主的标签和有限业务语义，使它难以表示“合法读取之后由 Agent 进行未授权转换”这一过程。CERT 原生不包含 Agent 身份、委托链、模型上下文、技能来源或下游服务状态证据。

TWOS 在游戏化红蓝对抗中使用真人参与者，因此比完全脚本化的数据更自然（Harilal 等，2017）。代价是规模、覆盖和可重复性有限。LANL Cyber1 提供真实认证、进程和网络事件，但缺少应用语义和完整威胁标签；Enron 提供真实企业通信（Los Alamos National Laboratory，2015；Enron，2004）。这两个数据集都没有同时提供组织目的、完整授权路径、内部威胁真值、Agent 轨迹、工具结果和下游损害。因此，它们适合作为行为锚点，却不能作为 AI 原生企业轨迹的真值。

ChimeraLog 将合成生成扩展到多个组织、基础模型、应用日志和系统遥测。其分布迁移实验说明，在 CERT 上表现良好的检测器换到新组织后可能显著下降。例如，Chimera 研究报告的 DS-IID F1 在 CERT 到 CERT 时为 0.955，在 CERT 到 Chimera-Finance 时为 0.464，反向训练时为 0.739（Yu 等，2026）。这说明需要跨组织评测，但攻击规格仍然是主要干预面。日志没有持续编码决定三个新威胁族的组织授权、人到 Agent 交接、来源谱系或技能有效性。

OrgForge-IT 使用确定性状态引擎、自然语言材料、独立真值和干净基线，把分诊、归因和损害分开（Flynt，2026）。其报告语料包含 51 天、4 个检测场景、2,904 条遥测记录、106 条信号和 2,798 条噪声记录。这比许多已有数据集更明确地支持标签核验和责任分析。它的场景覆盖仍然有限，跨组织有效性以及对人到 Agent 交接、跨部门目的和技能污染的覆盖还需要独立评估。

MOLE 研究有状态服务中 AI 操作账号的监测，并核验一个账号日是否造成实际服务损害（Muhamed 和 Smith，2026）。该基准包含 150 个 AI 操作账号、6 个团队、9 个服务和 30 个工作日。在一项跨生成器对照中，作者匹配账号、岗位、日期、有害目标和目标仓库，而较早的账号活动与服务状态仍然具有语料特异性。它的重点是在一个岗位、服务和威胁类型固定的合成组织中监测 AI 账号，因此委托有效性、跨部门业务目的、来源溯源和技能来源并不是主要干预变量。匹配账号、岗位、日期、目标和对象，不能回答谁发起了动作、哪个 Agent 执行了动作，或者复用技能是否扩张了授权范围。

因此，数据集的局限不只是公开轨迹是否合成。真实语料缺少语义和标签，受控语料简化组织状态，当前 Agent 语料只暴露因果链的一部分。常见基准都没有同时提供固定组织快照、单一受控授权或记忆干预、完整来源到执行者的溯源和已核验的下游效果。本文的数据问题是：在保持现有检测任务行为效用和跨组织迁移价值的同时，轨迹生成器能否加入这些字段。

C.2 检测方法

传统规则和用户实体行为分析通过阈值、同伴组偏离、访问序列和风险分数建立运行基线。机器学习方法在用户、会话或用户日特征上使用 SVM、CNN、自编码器、图神经网络和时序模型。ISFL-AE 以岗位和权限等内部人员属性为条件调节自编码器（Kim 和 Kim，2026）。双图 GCN 与 Bi-LSTM 方法把显式员工—资源图、学习得到的图和时间依赖结合起来（Yumlembam 等，2026）。这些方法说明岗位、资源关系和时间可以改善异常检测，但预测单位仍然是行为窗口或与账号绑定的活动。

较新的方法加入语言模型和跨源推理。Facade 在文档、SQL 以及 HTTP/RPC 日志上联合建模用户和企业资源，目标是高精度上下文异常检测。其部署研究报告审计事件流的误报率低于 0.01%，说明上下文过滤可以支持低误报预算（Kantchelian 等，2026）。Insight-LLM 用预训练编码器融合文本、情感、时间和图视图，在 CERT r4.2 和 r5.2 上报告的 F1 分别为 0.9712 和 0.9594（Song 等，2026）。LLMBA 为零信任网络学习时间与上下文行为表示（Yan 等，2026a、2026b）。MARS-ITD 把并行异常初筛和跨日志协作调查分开，在 CERT r4.2 上报告 94.44% 召回率、95.42% 准确率和 4.58% 误报率（Cheng 等，2026），Audit-LLM 用多种角色查询和交叉核对证据（Song 等，2024）。这些方法把研究从孤立事件推进到多视图证据和调查工作流。

它们的共同局限是语义目标。多数系统判断用户、账号、会话或用户日是否异常或有风险。异常分数不一定能判断业务目的是否违规、委托是否已过期、哪个 Agent 发出了动作，或者源和派生输出是否越过禁止边界。很少有方法同时区分人类发起者、Agent 执行者、运行时身份、委托链、源输入、技能或记忆溯源、受影响资源和最终接收者。大多数方法也在固定数据分布内评估。Chimera 的结果说明跨组织性能可能显著下降，当部门、工具、模型供应商或记忆策略变化时也会出现类似问题。

评测指标也限制了解释。Accuracy、F1、AUC 以及 PR-AUC 都不能单独表示低误报率下的复核召回、责任归因、检测延迟、下游损害，或者告警是否只因为目标干预而发生变化。OrgForge-IT 和 MOLE 开始区分分诊、归因、已核验损害和复核预算召回，却没有覆盖完整的 AI 原生组织状态。因此，一个只使用传统日志训练的检测器可能看似成功，实际学到的是账号或场景表面特征，而不是定义威胁的授权和溯源关系。

本文的检测问题由此确定。在相同工作流和固定误报预算下，加入组织、任务目的、委托、来源、Agent 运行时、技能、接收者和下游状态证据，是否能够改善违规检测、责任归因和损害识别。评测单位应是带溯源的组织轨迹，而不只是用户日或账号日。检测指标应包括低误报率召回、PR-AUC、校准、事件和会话级延迟、归因错误、未授权动作率以及跨组织迁移，并同时报告授权链完整性和反事实轨迹局部性的显式检查。
