企业 Agent 是否改变了内部威胁？

本页把“证明”定义为一条可核验、可反驳的结构性论证链。结论不写成“Agent 出现后内部威胁数量一定增加”，而写成：当企业 Agent 获得身份、委托权限、工具调用、跨会话记忆和 Agent 间协作能力后，内部威胁的主体、权限来源、攻击路径、持续性和归因对象不再能由只描述人类账号滥用的传统模型完整表达。

agent-mediated insider threatdelegated authorityprovenance gapcounterfactual security evaluation
当前可以成立的命题边界：已有规范、企业身份治理文档、真实漏洞和 Agent 安全研究共同支持“威胁模型发生结构性扩展”。它们尚不能单独证明 Agent 时代内部威胁发生率、损失规模或检测难度必然上升。后者必须通过匹配场景、单变量干预和跨域检测实验验证。

一、先把要证明的命题写清楚

命题精确定义证据状态如果不成立，论文如何收缩
H0 · 组织约束变化同一个资源操作是否构成合法行为，取决于主体、资源、操作、环境条件、部门关系、任务目的和审批路径。Agent 把这些约束带入委托、handoff 和跨部门信息流。NIST ABAC、Zero Trust、企业检测研究支持若所有资源都能用静态账号权限充分判断，组织图和任务目的不改变授权结果，则组织约束只能作为背景变量。
H1 · 主体与权限变化企业 Agent 成为具有独立身份或承载委托身份的非人类执行主体，权限可以沿委托链、角色继承和 Agent 间信任传播。规范与产品证据支持若 Agent 始终只是无权限的文本界面，则只能研究人类内部威胁的自动化工具。
H2 · 攻击路径变化攻击入口从人直接操作和凭证滥用扩展到检索内容、邮件、工具返回值、Agent 消息和记忆写入，危害通过规划和工具链落到企业状态。NIST、AgentDojo、EchoLeak 支持若所有外部内容都无法进入 Agent 上下文或工具链，则不声称存在 Agent 特有路径。
H3 · 时间与传播变化一次输入或一次记忆污染可以跨会话、跨 Agent 或跨工具继续影响后续行为，威胁状态不再只绑定单次人工操作。OWASP 2026 分类支持，需在 Morpheus 中实证若记忆完全隔离、短期有效且每步重新授权，则只保留委托权限扩展。
H4 · 归因变化同一工具动作可能同时关联人类发起者、Agent 身份、运行时身份、委托令牌、上游输入和记忆来源，单一账号到人的归因关系出现缺口。规范提出，需实验验证若每个动作都有不可伪造的来源、意图和权限链，则研究重点转为可审计性而非归因缺失。

H0–H4 是结构性变化命题。它们与“风险一定变大”或“所有 Agent 攻击都属于内部威胁”不同。后两项不能从本页证据直接推出。

二、传统内部威胁模型提供什么基线

01

主体是具有授权访问的人员

CISA 将 insider 定义为现在或曾经对组织资源具有授权访问或知识的人员，insider threat 是其利用这种授权访问或组织知识造成损害的可能性，行为可以是有意或无意的。

来源：CISA Insider Threat Mitigation

02

行为围绕账号和资源展开

MITRE ATT&CK 的 Valid Accounts 描述了对现有账号凭证的滥用，包括初始访问、持久化、权限提升和防御规避。合法访问本身也可能被用来降低被发现的概率。

来源：MITRE ATT&CK T1078

03

数据集以行为日志为主

CERT Insider Threat Test Dataset 提供背景行为和恶意行为的合成数据，适合校准登录、文件、邮件等传统活动，却没有完整的 Agent 身份、委托链、工具规划和记忆写入状态。

来源：CMU SEI CERT Insider Threat Test Dataset

因此，传统模型可以表达“员工滥用合法访问”。它不能自动表达“谁把什么权限委托给哪个 Agent、Agent 使用了哪个运行时身份、哪条外部内容导致了哪次工具调用、该状态是否在后续会话继续存在”。这组缺失变量就是需要证明的模型扩展点。

组织约束不是背景变量，而是合法性的状态变量

授权由多个属性共同决定

NIST SP 800-162 将 ABAC 定义为根据主体、对象、请求操作、环境条件以及策略、关系评估授权。员工角色和 Agent 身份因此不能脱离资源、操作、时间和环境单独解释。

来源：NIST SP 800-162

企业访问围绕资源和工作流

NIST SP 800-207 将用户、资产、资源和工作流纳入 Zero Trust 架构，并强调不能仅凭网络位置或资产归属产生隐式信任。组织依赖和工作流目的应进入授权判断。

来源：NIST SP 800-207

检测也需要用户–资源上下文

USENIX Security 2026 的 Facade 在企业文档、SQL 表和 HTTP/RPC 日志中联合建模用户与资源上下文。Selling the Dream 则显示身份关系和可见性变化会改变小型企业的内部风险。

来源：Facade · Selling the Dream

对 Morpheus 的含义：组织图、部门所有权、汇报路径、项目目的、审批链和临时委托决定了一步行为的合法解释。T2 的安全性不在于“员工访问了别的部门”，而在于多个局部合法请求被组合成偏离原始目的的信息流。T1 和 T3 也分别需要数据边界和技能来源的组织范围。

三、结构变化来自哪些新的系统原语

企业 Agent 身份Agent 被纳入身份、生命周期和资源访问治理。
委托与继承Agent 可代表用户或上游 Agent 获取受限或继承的权限。
工具与 API模型输出进入邮件、文件、日历、数据库等状态变更链路。
记忆与消息上下文、技能和 Agent 间消息可能跨会话或跨主体传播。
归因与审计动作需要同时追溯主体、来源、意图、授权和运行时。

这不是把“Agent”当作新的员工类别，而是把原来的 human → authorized action 扩展成一条带状态和来源的执行链。

传统：   human principal → account/permission → resource action → harm
扩展：   source/input → human or agent context → delegated identity
         → planning → tool/API call → enterprise state or data flow
         → memory/message persistence → later action → harm

需要记录：principal, agent_id, runtime_id, session_id, delegation_chain,
          tool, input_provenance, memory_write, policy_decision, result

四、六条独立证据链

证据链可直接观察的事实支持的推断不能推出的结论对 Morpheus 的更新
E0
组织约束决定合法性
访问控制与企业检测证据		 NIST ABAC 将主体、对象、操作和环境条件纳入授权策略。NIST Zero Trust 把用户、资产、资源和工作流作为保护对象。Facade 在企业日志中联合使用用户与资源上下文。 组织角色、部门所有权、任务目的、审批关系和时间窗口不是日程装饰，而是判断“合法访问是否偏离目的”的状态变量。 这些来源不能证明某个组织图一定比另一个组织图更真实，也不能单独证明层级会议生成的轨迹质量更高。 所有三个 JSON 场景都增加 organization_constraints、department ownership、purpose、approval/delegation 和 matched-pair control。
E1
Agent 已进入企业身份治理
行业基础设施证据		 Microsoft Entra Agent ID 文档把 AI Agent 的身份、所有者、生命周期、访问包和资源保护纳入企业级身份管理，明确提出管理、治理和保护 Agent identities。 企业 Agent 已经被设计成需要独立治理的非人类身份，权限来源不能只用员工账号解释。 不能据此证明所有企业都已采用相同架构，也不能证明威胁发生率上升。 日志加入 Agent identity、owner/sponsor、runtime、token scope 和 delegation chain。
E2
Agent 安全规范新增专门风险
安全分类证据		 OWASP Agentic Applications Top 10 2026 单独列出 Identity & Privilege Abuse、Memory & Context Poisoning、Insecure Inter-Agent Communication 和 Tool Misuse。 动态信任、委托权限、缓存凭证、共享记忆和跨 Agent 消息已经被安全框架视为不同的风险结构。 分类本身不是事故频率统计，也不是对 Morpheus 生成轨迹质量的验证。 攻击模板从“员工做了什么”扩展为“权限如何传播、内容如何入上下文、记忆如何持久化、消息如何影响下游 Agent”。
E3
标准风险模型确认数据与人机交互边界改变
政府风险框架证据		 NIST AI 600-1 将 Data Privacy、Human-AI Configuration 和 Information Security 作为风险视角，并指出 GAI 扩大攻击面，间接 prompt injection 可以通过被检索数据远程影响集成应用。 风险入口可以位于外部数据，危害通过人机配置、模型上下文和互联系统传递。 不能据此证明某个具体 Agent 一定会执行攻击，也不能取代企业数据上的干预实验。 把 input source、retrieval、context、tool action 和 data flow 作为同一条可审计轨迹。
E4
生产系统出现跨信任边界案例
真实漏洞与事件证据		 EchoLeak 研究描述了针对 Microsoft 365 Copilot 的 zero-click prompt injection。NVD 记录 CVE-2025-32711 为未授权攻击者通过网络披露信息，论文描述单封构造邮件触发远程数据外泄，且不需要用户交互。 攻击来源、执行主体和数据权限可以分离。外部内容可以借助企业 Agent 的内部访问能力完成数据流出。 EchoLeak 不是传统定义下的员工内部威胁事件。它证明的是 Agent-mediated threat path，不能直接证明员工恶意行为增多。 内部威胁标签必须区分 source、authorized principal、agent executor 和 affected resource。
E5
工具型 Agent 的攻击面可重复实验
学术实验室证据		 AgentDojo 在邮件、银行和旅行等任务中评测工具调用，包含 97 个任务和 629 个安全测试案例，研究外部工具返回数据对 Agent 的 prompt injection 影响。 攻击路径位于“外部数据 → Agent reasoning → tool call → 环境状态”，不只位于用户输入框。 AgentDojo 的环境不包含企业部门层级、员工日程和内部威胁标签。 采用执行器验证工具前置条件、后置状态和每一步 provenance，不使用最终文本作为唯一标签。

来源：NIST SP 800-162 · NIST SP 800-207 · Facade · Selling the Dream · Microsoft Entra Agent ID · OWASP Agentic Applications 2026 · NIST AI 600-1 · NVD CVE-2025-32711 · EchoLeak · AgentDojo

五、为什么这不是“把几个工程模块拼起来”

层级会议

工程实现是分层生成日程。科学变量是组织目标、依赖和授权如何传播到个人轨迹。

constraint propagation

快速路由

工程实现是区分简单和复杂行为。科学变量是风险、复杂度和不确定性如何改变执行策略与成本。

risk-aware control

人–Agent 协作

工程实现是 Planner 与 Tool Agent 的 handoff。科学变量是意图、委托和执行动作之间的可观测偏差。

authority-aware handoff

Skill/Memory

工程实现是保存可复用流程。科学变量是来源、权限范围、有效期和污染状态如何决定复用结果。

provenance-constrained reuse
论文真正要证明的关系：去掉或改变某一个组织/权限/记忆变量后，轨迹的结构性质会按可预期方向变化。模块只有在承载这些变量、产生可复现实验差异时，才从实现细节变成方法的一部分。

六、Agent-mediated insider threat 的形式化定义

G = organization graph             组织层级、部门所有权和依赖关系
K = organizational constraints     角色、目的、审批、时间和资源范围
H = human insider                 人类内部主体
A = authorized enterprise agent   被企业授权的 Agent
C = compromised context           被操纵的输入、检索内容、记忆或消息
P = delegated privilege            委托或继承的权限
U = tool/API execution             对企业工具或系统的调用
M = persistent/shared state        跨会话、跨 Agent 的记忆或流程状态

授权判断：        Policy(subject, object, operation, environment, K, G)
传统内部威胁：  H + authorized_access(G, K) + misuse → harm
Agent-mediated： (H | A | C) + P + U + (optional M)
                  + unauthorized data flow or state change → harm

这里的 C 不等于内部人员。它表示威胁上下文可能被外部内容操纵。为了保持内部威胁定义的严谨性，论文应把“攻击来源”和“执行所用的企业授权”分开标注。只有当危害依赖企业内部的授权、信息或 Agent 执行链时，才把该样本纳入 agent-mediated insider threat 评测。

七、证明流程 Road Map

R0

锁定命题和术语边界 已完成

把命题从“内部威胁变多”收敛为“组织约束、攻击主体、权限承载、路径、持续性和归因结构扩展”。明确“Agent 攻击”不自动等于“内部威胁”，必须同时检查企业授权或内部信息依赖。

  • 产物：H0–H4、传统模型与扩展模型、反驳条件。
  • 更新来源：CISA 定义、MITRE Valid Accounts、NIST ABAC、NIST Zero Trust、现有 ICML 研究路线。
R1

建立传统基线 已完成

用 CISA、CERT 和 MITRE 描述传统内部威胁的主体、授权访问、资源操作与行为检测对象。把 CERT 作为行为锚点，而不是假设它包含 Agent 轨迹。

  • 产物：基线字段表、传统轨迹 schema、可对齐的登录/文件/邮件特征。
  • 更新程度：已确认传统数据适合做时间、通信和资源访问分布校准，不能提供完整的 Agent 意图和委托来源。
R2

证明企业系统已经出现新的身份承载 已完成

用 Microsoft Entra Agent ID 说明企业基础设施正在为 Agent 提供身份、生命周期和资源访问治理。用 OWASP ASI03 补充动态信任、委托权限、继承凭证和 attribution gap 的安全含义。

  • 产物：Agent identity、runtime、session、delegation chain 字段设计。
  • 更新程度：H1 获得行业基础设施和安全规范的双重支持，尚未获得 Morpheus 数据上的行为统计支持。
R3

证明攻击路径不再只经过人类直接操作 已完成

用 NIST AI 600-1 的间接 prompt injection 描述、Greshake 的间接注入研究和 AgentDojo 的工具型测试，建立“外部数据 → Agent 上下文 → 工具执行”的可重复路径。

  • 产物：输入来源、检索、上下文、工具调用和状态变化的 typed event graph。
  • 更新程度：H2 获得规范与实验研究支持。AgentDojo 不包含企业组织结构，因此企业内生路径仍需要自建沙箱验证。
R4

用真实生产案例验证边界穿越 已完成

用 EchoLeak 作为边界案例。它显示未授权外部攻击者可以通过一封构造邮件触发企业 Copilot 的数据外泄链。论文中把它作为“来源与执行权限分离”的证据，不把它改写成员工内部威胁案例。

  • 产物：source–principal–executor–resource 四元标注。
  • 更新程度：H1/H2 得到生产漏洞支撑，H3/H4 仍需在受控环境中做持续性和归因实验。
R5

构造同状态反事实实验 待实现

固定组织图、员工画像、日程、工具和初始状态，分别只改变委托权限、输入来源、记忆写入、Agent 间消息或内部意图，生成 benign / agent-mediated / insider 成对轨迹。

  • 问题：单一干预是否只改变可解释的局部子轨迹？
  • 指标：权限继承深度、工具可达范围、跨部门数据流、记忆传播长度、归因歧义、未授权动作率。
R6

在 Morpheus 中实现安全事件溯源 待实现

在已有层级会议、行为路由、双 Agent handoff 和 SkillMemory 的最小改动基础上，补齐事件来源和授权链。每个高风险工具事件都必须能回到触发输入、计划步骤、Agent 身份、权限判定和状态结果。

  • 实现入口：src/hierarchical_meeting.py、src/behavior_router.py、src/skill_memory.py 及现有攻击 JSON schema。
  • 验收：无来源的记忆写入、无授权的工具调用、无法解释的跨部门读取都应被 verifier 标记。
R7

验证检测与数据集效用 待实现

用当前内部威胁检测方法分别在传统日志、Agent 正常轨迹、Agent-mediated 威胁轨迹和跨组织测试集上评测。检测器表现好，说明生成数据能支撑安全任务。检测器表现差，则分析是分布偏移、归因缺口、长程依赖还是标签不可审计。

  • 指标：PR-AUC、低误报召回、检测延迟、跨组织泛化、合成训练真实测试、真实训练合成测试。
  • 不能用单个检测器的高分反向证明轨迹真实，必须先报告轨迹级约束和反事实一致性。
R8

形成论文级结论 待验证

只有当 R5–R7 显示新增变量能产生稳定、可解释、跨组织复现的轨迹差异，并且传统模型在这些路径上出现可定位的覆盖缺口，才能写成“企业 Agent 改变了内部威胁模型”。否则按证据收缩为“Agent 扩展了企业安全行为模拟的状态空间”。

  • 最终主张：结构变化 + 可测量后果 + 可审计生成方法。
  • 不主张：Agent 必然更危险、内部威胁数量必然增加、所有 Agent 攻击都是 insider threat。

八、最小实验阶梯：每一步只回答一个问题

实验问题最小设置关键指标支持哪条命题
Q0 · 组织约束同一个工具动作在不同部门、任务目的或审批路径下，授权结论是否变化？固定主体、对象和操作，只改变部门关系、任务目的、时间窗口或委托范围。策略决策差异、角色–资源一致性、依赖路径违反率、信息流越界量。H0
Q0b · 结构可表达性传统事件 schema 是否无法无损表达 Agent 事件？同一个工具动作分别由员工直接执行、员工委托 Agent 执行、跨 Agent 转发执行。字段缺失率、来源链完整率、唯一归因率。H1、H4
Q1 · 权限反事实只改变 delegation scope 是否改变工具可达集合？固定组织、目标和输入，分别授予直接权限、最小委托权限、过宽继承权限。可达工具数、越权调用率、权限继承深度、状态影响范围。H1、H2
Q2 · 路径反事实外部内容能否在不改变员工初始目标的情况下改变 Agent 工具动作？固定员工任务，替换邮件或检索结果中的一条内容，使用离线企业工具沙箱。动作差异、外泄量、跨系统调用数、攻击成功率。H2
Q3 · 持久化反事实一次记忆或 Skill 写入是否能影响后续会话或其他 Agent？比较无记忆、隔离记忆、污染记忆、共享污染记忆。影响会话数、传播深度、持续时间、污染复用率。H3
Q4 · 归因反事实只观察传统账号日志时，能否唯一识别真实执行主体和授权来源？隐藏或保留 Agent identity、handoff 和 delegation fields，比较审计器。归因准确率、证据链完整率、审计时间、误报归因率。H4
Q5 · 下游安全效用新增轨迹字段是否改变内部威胁检测的跨域表现？传统日志训练/Agent 轨迹测试，反向再做一次，比较现有检测器与加入 provenance 的检测器。PR-AUC、低 FPR recall、检测延迟、跨组织性能下降。H2–H4 的后果

九、什么结果才算“证明成功”

必要结果 A · 结构差异

在相同组织和目标下，Agent 版本出现可重复的委托链、工具链、记忆状态或跨 Agent 消息，而传统版本没有这些状态。

必要结果 B · 因果可控

只改变一个变量时，变化集中在预期的权限、数据流或持续性指标上，未授权的副作用可以被执行器发现。

必要结果 C · 安全后果

传统账号级检测或审计在隐藏 Agent 证据时出现可解释的漏报、延迟或错误归因，加入 provenance 后得到改善。

证伪条件：若所有 Agent 都是无状态、无权限的文本接口；所有高风险动作均需人工逐步确认；不存在跨会话记忆、跨 Agent 委托或跨系统工具链；且传统账号日志能够唯一恢复来源、授权和执行者，则“内部威胁模型发生结构性变化”不成立。此时论文应改为研究 Agent 对传统内部威胁模拟效率的影响。

十一、截至目前的结论

可以写入论文引言的版本：企业 Agent 把传统内部威胁中的“合法访问主体”扩展为由组织约束、人类主体、Agent 身份、委托权限、工具调用和持久化上下文共同组成的执行链。规范和真实案例显示，这条链引入了新的攻击入口、权限传播方式和归因对象。Morpheus 的研究问题不是生成更多攻击日志，而是在组织约束下生成这类可审计轨迹，并用反事实干预检验新增变量是否造成可解释的安全后果。
目前仍不能写入论文的版本：Agent 已经导致内部威胁数量增加、损失更大、检测一定更难，或所有 Agent 攻击都应归为内部威胁。这些句子需要 R5–R7 的实验数据，而且 EchoLeak 等外部攻击案例不能直接替代员工内部威胁证据。
核验日期：2026-11-20 · 相关路线：ICML 2027 研究路线 · 三类内部威胁场景研究 · 多 Agent 数据与轨迹调研 · 本页面记录的是证明路线和证据边界，不把尚未运行的实验写成结果。
