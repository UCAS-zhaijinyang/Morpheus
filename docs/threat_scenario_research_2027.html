Morpheus 三类内部威胁场景调研与实验依据

版本：2026-11-19 · 目标：USENIX Security 2027 方向验证与源码场景更新

本文把 Morpheus 的攻击模板收敛为三个可控的内部威胁族，分别覆盖 AI 数据边界、组织流程权限和 Agent 流程记忆。选择标准是威胁是否能被组织约束、员工行为模式、流程复用和人—Agent 工具执行共同表达，并且能形成可审计的安全评测实验。

研究决策。三个场景足以构成论文的主实验集合。每个场景需要生成正常轨迹、威胁轨迹和单一干预下的反事实轨迹。三个名称描述研究场景族，不宣称创造了三个全新的攻击技术。

为什么这三个方向值得研究

T1

AI 中介的数据边界滥用

员工以合法身份读取企业数据，再通过企业 Agent、外部 AI 服务或生成结果转发，使源数据的授权范围与输出范围发生分离。

AI data flowhuman–Agent handoffsemantic leakage
T2

跨部门流程型权限滥用

员工利用项目交接、临时替代、审批和同事协作取得分散信息。单个请求合理，跨部门长期信息流却偏离原始业务目的。

organization graphdelegated accesslow-and-slow
T3

Skill/Memory 污染与越权复用

Agent 复用缺少来源、范围或有效期检查的流程技能，把旧任务的工具、对象或收件人带入新的权限环境。

近期安全研究提供的依据

AI 数据边界和 Agent 轨迹。 NIST 的生成式 AI 风险框架把数据隐私、信息安全和 Human–AI Configuration 作为独立风险视角，并指出风险可能来自人的误用、系统的工具访问以及人与 AI 的交互。OWASP GenAI Security Project 2025 将 Prompt Injection、Sensitive Information Disclosure、Supply Chain、Data and Model Poisoning 和 Excessive Agency 列为 LLM 应用的主要风险。它们共同支持把 T1 和 T3 建模为企业数据流与工具执行问题。
日志和 Agent 安全的实证信号。 USENIX Security 2026 的 Context Contamination 工作在 12,847 条日志上研究被动提示注入，其中 2,569 条为对抗样本。作者报告基线下最高 88.2% 的攻击成功率，并显示分层防御后仍有残余风险。这说明日志内容、模型上下文和安全分析输出之间需要被联合审计，T1 的 Prompt、Source、Output 和 Recipient provenance 具有明确的评测对象。
流程轨迹的安全审计。 USENIX Security 2026 的 MATE 构建了超过 140K 条策略条件轨迹，并使用真实设备轨迹评估移动 Agent 策略审计。这项工作表明合成轨迹可以服务于安全审计，但轨迹必须绑定策略、任务和违规原因。Morpheus 的企业场景把同样的思想扩展到组织依赖、角色权限和企业工具链。
企业内部威胁依赖上下文。 USENIX Security 2026 的 Facade 在企业文档访问、SQL 表访问和 HTTP/RPC 请求日志上建模用户与资源上下文，并报告低于 0.01% 的误报率。论文指出内部威胁行为通常混在大量合法行为中。这个结论直接支持 T2 的研究问题，即检测器是否能识别跨部门、长期、单步合法但整体异常的信息流。
组织关系和非正式权限。 USENIX Security 2026 的 Selling the Dream 分析了 38 个高风险小型企业案例记录，并访谈了 16 名企业经营者。研究关注朋友、家人和伴侣参与企业运营后产生的身份关系、访问控制和可见性风险。它支持将项目交接、临时委托、信任关系和部门依赖作为 T2 的行为生成变量。
Skill 供应链已有现实风险。 USENIX Security 2026 的 Do Not Mention This to the User 分析了两个技能注册表中的 98,380 个 Agent Skills，确认 157 个技能包含恶意行为，涉及 632 个漏洞和 13 种攻击技术。研究还发现凭据窃取和嵌入式对抗指令是主要策略。这个结果为 T3 的技能来源、污染、复用和验证实验提供了直接依据。

三个场景的威胁定义

场景攻击者能力核心安全边界可观察轨迹
T1
AI 中介的数据边界滥用		员工可以访问任务相关数据并调用 AI 或通信工具。源数据、模型上下文、生成输出和接收者必须符合数据使用政策。数据访问、Prompt、Source objects、模型调用、输出对象、收件人和外部服务。
T2
跨部门流程型权限滥用		员工可以参加项目、申请临时授权和请求同事协作。合法角色和临时委托不能被组合成超出任务目的的信息聚合路径。会议和日程、部门依赖、审批、邮件、权限变化、文件谱系和跨部门信息流。
T3
Skill/Memory 污染		攻击者可以贡献或触发检索一个流程项，或者让一个不安全流程被记录为可复用技能。技能必须携带来源、角色范围、资源范围、前置条件、有效期和验证结果。技能写入、检索、来源轨迹、权限检查、Plan–Execute handoff、工具调用和结果。

与原有 15 个模板的关系

仓库原有 15 个场景主要集中在知识产权窃取、数据外传、系统破坏、欺诈和非故意访问。它们适合做基础回归场景，但大量模板共享“权限提升—访问敏感文件—外传”的结构，并且没有统一记录 AI 上下文、组织信息流或流程技能来源。

研究缺口。 当前模板描述了攻击者想做什么，却没有把数据源、组织关系、授权目的、Agent 上下文和技能来源作为可验证状态。因此，仅使用旧模板难以回答三个新的安全问题。新模板保留原有 what、how 和日志数据源接口，同时补充 threat_model、research_questions 和 framework_refs。

源码中旧的 JSON 文件仍保留以兼容历史命令，自动攻击脚本的主列表已经切换到三个新场景。这样可以复现旧实验，也可以把新场景作为当前论文的主评测集合。

逐步实验问题

  1. T1。 在相同源文件访问下，加入 Prompt、模型上下文、输出和收件人日志，是否能提高 AI 数据边界违规检测能力？
  2. T2。 分层会议和组织依赖是否能生成比全员规划更合理的审批、交接和跨部门信息流？
  3. T3。 带来源、权限和有效期检查的流程技能，是否能减少越权复用和污染扩散，同时保持正常任务的流程复用收益？
  4. 统一评测。 生成数据训练的检测器能否迁移到真实或公开企业行为数据？检测器在新场景上失败时，轨迹级验证能否排除合成伪影造成的假失败？
解释边界。 检测器效果高只能说明数据对该检测任务具有安全效用，不能单独证明行为真实。检测器效果低只有在轨迹约束、分布校准、专家检查和多检测器实验都通过后，才可以作为现有检测方法存在盲点的证据。
