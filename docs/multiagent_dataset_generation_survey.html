MORPHEUS · MULTI-CONFERENCE RESEARCH SURVEY · 2026-11-18

多 Agent 如何生成数据、轨迹与环境：面向企业内部威胁行为模拟的调研

本文调研 ICML、ICLR、NeurIPS、CVPR、IJCAI、AAMAS、ACL、KDD 和 ACM Multimedia 的最新论文，筛选使用 Agent 或多 Agent 机制生成任务数据、交互轨迹、仿真环境、行为标签、评测样例或可复用流程的工作。结论是：Morpheus 不应被包装成通用多 Agent harness，而应被定义为 组织约束下的企业 Agent 行为轨迹生成与反事实内部威胁模拟。

1. 调研范围、筛选标准与证据边界

时间范围以截至 2026 年 11 月 18 日能够访问的最新官方接收论文、会议 proceedings 或官方 virtual paper list 为主。对 ICML 2026，使用用户指定的 ICML 2026 Guide CN，该页面标注 6567 篇论文并提供 Agent 与工具使用、多智能体、安全防御、安全等分类。其他会议使用官方列表或官方论文页。

“相关”分成五级。A 直接生成 Agent 生成数据集、任务、标签或训练样例；B 轨迹/环境 Agent 生成交互轨迹、状态转移、环境或用户行为；C 安全评测数据 Agent 生成攻击案例、风险场景或安全测试轨迹；D 流程/技能 Agent 从经验中沉淀可复用流程；E 邻近证据 只提供评测原则、真实数据锚点或单个模块。只提出多 Agent 算法、只使用现成数据集、只做最终结果评测而不生成数据的论文不进入主样本。

避免过度声称：这里的“调研所有论文”指对可访问的会议官方条目做标题/关键词穷举筛选，再对高相关候选逐篇读取官方摘要或 proceedings 首页；不是声称对约两万条论文全文逐篇精读。正文会区分“直接证据”和“邻近证据”，并保留低相关候选附录。

3. 文献形成的五类生成范式

A

任务/轨迹流水线

从原子任务、环境探索或需求文档出发，自动生成可执行任务，再由 executor 采样轨迹，最后由 verifier 或测试执行器过滤。

B

环境/状态转移

先构造环境、网站、应用或状态转移，再让 Agent 在其中探索。环境的可执行性和状态闭环比生成文本更重要。

C

行为/用户模拟

用 persona、认知偏差、非合作行为或多角色交互生成用户行为，从少量真实历史扩展到可控场景。

D

流程/技能记忆

从成功轨迹抽取触发条件、步骤、工具和终止条件，在新任务中检索、适配和验证，形成 procedural memory。

对 Morpheus 的核心启示：生成“更像人”的文字不是主要问题。应该生成一个带组织状态、权限、日程、手动/自动交接、工具事件、等待和失败恢复的结构化轨迹。文本只是一种观察，而不是轨迹本体。

4. 重点论文逐篇分析

4.1 任务和交互轨迹：从“让模型写任务”走向“环境中发现任务”

AgentSynth: Scalable Task Generation for Generalist Computer-Use Agents · ICLR 2026

类别：A/B；规模：6000+ 任务；单条轨迹平均成本约 0.60 美元；显式多 Agent：△，更准确地说是 agentic pipeline。

方法：利用信息不对称构造简单可生成、组合后更难的子任务，通过改变子任务数量控制长程难度；再生成任务和轨迹数据。摘要报告从难度 1 到难度 6，SOTA Agent 成功率从 18% 降到 4%。

质量控制：主要依赖可执行任务、组合难度和最终轨迹质量，成本显著低于人工标注。对 Morpheus：企业任务也应先从“查看邮件、登录、创建日程、发送附件”等原子行为开始，再按组织依赖和时间跨度组合成跨部门长程任务；难度控制可以来自跨部门数量、权限边界和隐含目标，而不是只增加步骤数。限制：它没有组织权力结构，也没有 benign/insider 同状态反事实。

Scaling Synthetic Task Generation for Agents via Exploration (AutoPlay) · ICLR 2026

类别：A/B；显式角色：explorer → task generator → executor → verifier；20 个 Android 应用生成 20k 任务，13 个 Ubuntu 应用生成 10k 任务。

方法：Explorer Agent 先系统探索环境状态和功能，Task Generator 用探索轨迹与任务规范生成环境锚定的任务，Executor 生成 demonstrations，Verifier 判断是否可执行和完成。训练 UI Agent 后，移动端和计算机端成功率分别获得最高 20.0% 和 10.9% 的提升，Verifier reward 的 RL 进一步提升 5.7%。

吸收：Morpheus 应先探索企业工具状态图，再生成员工任务；任务不应由语言模型凭空编写。邮件、日历、文件权限和内部系统要有可查询的状态、前置条件和后置条件。不能照搬：AutoPlay 的环境是应用界面，企业内部威胁还需要身份、权限和组织事件的因果约束。

TaskCraft: Automated Generation of Agentic Tasks · ICLR 2026

类别：A；41k 工具任务、12.6k 工具交互轨迹、5k 多跳分解。

方法：从原子任务出发，按 depth 和 width 逐步扩展，配合 rejection sampling 和 LLM linguistic analysis 验证任务，随后采样轨迹和多跳分解用于 SFT/RL。它说明“任务生成”和“轨迹生成”应拆成不同阶段。

对 Morpheus：部门目标、个人计划和员工事件可以成为不同宽度/深度的任务图；轨迹标签应同时保留任务结构、计划结构、工具结构和实际执行结构，才能测量计划–执行偏差。风险：如果只用 LLM judge，可能把表达通顺误判为企业流程正确，必须加入权限和状态执行器。

WebShaper: Agentically Data Synthesizing via Information-Seeking Formalization · ICLR 2026

类别：A；显式角色：seed task → agentic expander → retrieval/validation。

WebShaper 用集合论形式化 Knowledge Projection，控制信息寻求任务的推理结构；Expander 在检索和验证工具支持下逐步扩展问题。可迁移的要点不是“集合论”，而是把任务的隐含结构显式化，并让每次扩展都留下可检查的状态。

对 Morpheus，可以把企业任务形式化为 身份/角色 × 组织对象 × 权限 × 时间窗口 × 工具状态 × 目标依赖。员工日程的生成不是润色自然语言，而是对可见目标、依赖和权限做结构化投影。

APIGen-MT: Agentic Pipeline for Multi-Turn Data Generation via Simulated Agent-Human Interplay · NeurIPS 2025

类别：A/B；角色：任务蓝图生成器、LLM reviewers、模拟人、Agent；开放 APIGen-MT-5k 数据。

方法：第一阶段生成带 ground-truth actions 的 task blueprint，由多个 LLM reviewer 迭代反馈；第二阶段让模拟人和 Agent 进行完整多轮交互。论文训练 1B–70B 的 xLAM-2-fc-r，在 τ-bench 和 BFCL 上验证。

对 Morpheus：员工的真实行为应有“意图蓝图”和“可观察行动”两层。部门负责人产生的是组织约束蓝图，员工模拟器产生的是有限信息下的意图，工具 Agent 产生可执行动作；每一层都需要 reviewer 或执行器校验。关键差异：APIGen-MT 的人是模拟交互角色，Morpheus 的人还必须受组织权力、角色习惯和内部目标约束。

T1: A Tool-Oriented Conversational Dataset for Multi-Turn Agentic Planning · NeurIPS 2025

类别：A/B；9 个领域，包含工具依赖、缓存、短期/长期记忆和动态重规划。

T1 的价值在于把多轮工具依赖纳入数据单元，而不是只提供问答。它要求 Agent 判断是否重新计算或复用缓存结果。对企业轨迹而言，邮件线程、会议纪要、文件版本和身份状态同样是缓存对象；员工的“看起来合理”取决于是否正确处理了信息新鲜度和跨日记忆。

WebSTAR: Scalable Data Synthesis for Computer Use Agents with Step-Level Filtering · ACL 2026

类别：A/B；官方摘要标题明确强调 scalable synthesis 和 step-level filtering。

这条工作补充了一个对 Morpheus 很重要的原则：过滤粒度必须下沉到每一步。企业行为轨迹中，一条最终完成的任务可能包含未经授权的中间读取、错误收件人、跨部门越权或不合理的时间跳转；只看最终成功会把这些错误吞掉。Morpheus 的 verifier 应对每一个工具事件检查身份、权限、状态变化和来源。

SWE-smith: Scaling Data for Software Engineering Agents · NeurIPS 2025

类别：A/B；从 128 个 GitHub 仓库生成 50k 软件工程实例和轨迹。

SWE-smith 的重要性在于它不是让 LLM 编一组漂亮任务，而是从真实代码库构造执行环境，再自动生成会破坏现有测试的任务实例。对 Morpheus 的启发是：企业数据应锚定真实工具 schema、组织状态和日志约束；合成任务必须能在沙箱中执行、复现和验证。真实企业日志可用作行为分布锚点，但不能直接当作完整意图标签。

GUI-ReWalk: Massive Data Generation for GUI Agent via Stochastic Exploration and Intent-Aware Reasoning · IJCAI 2026

类别：B；显式机制：随机探索 → 意图推断 → 长程多应用流程。

GUI-ReWalk 让前期随机探索模拟试错，后期用推理恢复目标，使数据同时拥有多样性和意图结构；论文报告较高的轨迹熵和更真实的用户意图。对于企业行为，登录、打开邮件、切换窗口、暂缓回复等“低语义动作”不能被全部删掉，它们是员工行为节奏的一部分；但危险动作必须由意图和权限解释。

WebGym: Scaling Training Environments for Long-Horizon Visual Web Agents · CVPR 2026

类别：B；约 300k 任务，11 个真实网站的确定性/可评价环境，异步 rollout。

WebGym 证明了高质量轨迹生成需要可扩展环境、明确 reward 和大量异步 rollout，而不是只增加 prompt。对 Morpheus，邮件、日历、文件和身份系统需要统一的 event-sourced sandbox；生成器和检测器都应读取同一状态转移。其局限是没有企业组织层级和内部威胁身份。

4.2 环境和行为模拟：真实度来自状态动力学、角色差异和互动反馈

LLMEvalRec: An Agentic Framework for Simulating Users to Evaluate News Recommendation Systems · AAMAS 2026

官方 proceedings：EFZY6916；类别：B/C。

LLMEvalRec 从少量 reading histories 生成用户画像，让用户 Agent 产生动态行为，并用 Guided Episodic Search 优化 prompt；模拟评测排序与真实评测达到 0.97 Spearman 相关。它最接近 Morpheus 的“员工行为模拟”目标：用户不是静态 persona，而是会随内容、历史和环境变化。可迁移的是小样本校准、行为反馈和生产验证；不能直接把新闻点击偏好当作企业内部威胁。

UrbanMix: LLM-Guided Simulation of Mixed Autonomy Traffic with Heterogeneous Behavioral Profiles · IJCAI 2026

类别：B；SUMO 城市交通；人类驾驶员、谨慎/激进 AV、配送机器人等异质角色。

UrbanMix 把不同角色放入同一个仿真环境，再让 LLM planner 在有界动作接口内设定政策，regulation shield 维护基础设施约束。对 Morpheus 的启发是“角色不是 prompt 里的性格描述”，而应有不同的目标、观测和可用动作；部门负责人、普通员工、外部协作者和恶意内部人都应有不同的观测边界。

BotVerse: Real-Time Event-Driven Simulation of Social Agents · AAMAS 2026

类别：B/C；事件驱动社会仿真；从 Bluesky 实时内容流摄取事件，但将交互隔离在合成环境。

BotVerse 说明真实度和安全性可以同时设计：外部内容作为状态输入，Agent 只在隔离的 Synthetic Social Observatory 内互动，支持时间模式、认知记忆和 disinformation red-teaming。对内部威胁模拟，应把真实企业数据用作统计/事件先验，在合成身份和离线工具沙箱中生成轨迹，避免把真实凭据或真实个人行为放入执行回路。

DecompGAIL: Learning Realistic Traffic Behaviors with Decomposed Multi-Agent GAIL · ICLR 2026

类别：B；多 Agent 轨迹生成/模仿学习；WOMD Sim Agents 2025。

DecompGAIL 发现一个对“行为真实性”很有价值的现象：在多 Agent 轨迹中，邻居之间的不真实互动会错误惩罚 ego 的合理行为。它把真实性分为 ego–map 和 ego–neighbor，并用距离加权邻域奖励。对应到 Morpheus，应把员工自身的任务合理性、员工–部门依赖和跨部门信息传播分开评估，避免一个部门的合成错误把另一个员工的合理动作判成不真实。

CogEA: A Multi-Agent System for Cognitive Ability Annotation of Exercises by Simulating Human Behaviors · AAMAS 2026

类别：A/C；角色：administrator、student、teacher；用模拟行为生成认知能力标签。

CogEA 是与用户任务最相似的“多 Agent 模拟行为来标注数据”例子之一。它让虚拟学生解题，虚拟教师和管理员补全、筛选、标注数据。迁移到企业场景，可以让 manager、employee、reviewer 共同产生任务意图、执行轨迹和标签。但它是 demonstration track，标签质量仍需要真实员工或专家校验；因此 Morpheus 应把内部威胁标签写成“干预来源 + 状态证据”，而不是只由一个 LLM 角色裁决。

Beyond Rule-Based Agents: Active Markov Games for Realistic Multi-Agent Interaction · CVPR 2026

类别：B；Active Markov Game；共同演化 ego policy 与多样 opponent policy。

该工作把环境转移和奖励显式依赖于 Agent 策略的演化，从而摆脱固定、不会响应的对手。企业内部威胁中，员工、主管和检测器同样会相互适应：权限变化会改变员工策略，员工行为会改变主管审查和检测器告警。Morpheus 可以借鉴“对手池/角色池”的思想，但需要把对手替换为有组织身份和权限约束的反事实角色。

4.3 流程和技能：skill 必须是可执行、可验证、有来源的状态机

ProcMEM: Learning Reusable Procedural Memory from Experience · ICML 2026

类别：D；Skill-MDP；skill 由 activation、execution、termination 条件构成；非参数 PPO + PPO Gate。

ProcMEM 将被动 episodic narrative 转为可执行 Skill，并用候选生成、验证和 score maintenance 维持紧凑记忆。它是 Morpheus 的 skill 设计最直接的理论依据。必须吸收的是三件事：触发条件、执行条件、终止条件；技能来源和可靠性；复用时的验证。不能只保存 steps 文本，也不能把向量检索命中率叫作 skill reuse。

Meta Context Engineering via Agentic Skill Evolution · ICML 2026

类别：D；meta-level agent 演化 context-engineering skills，base-level agent 执行并优化 context artifacts。

MCE 把 skill 本身作为可演化对象，强调 skill、执行记录和评估之间的闭环。对 Morpheus，部门流程不能被一次性写死；但任何演化都应带 provenance、审批/授权范围和回滚信息。MCE 的“技能演化”不能替代企业安全约束，尤其不能允许通过 prompt 演化绕过权限。

Learning Hierarchical Procedural Memory for LLM Agents through Bayesian Selection and Contrastive Refinement (MACLA) · AAMAS 2026

类别：D；从轨迹抽取层级程序记忆；Bayesian reliability、expected utility、成功/失败对比精炼。

MACLA 将 LLM 冻结，把适应放在外部层级程序记忆中，报告跨 ALFWorld、WebShop、TravelPlanner、InterCodeSQL 的平均提升。它给 Morpheus 的重要启示是：员工流程可以外置更新，减少每次重新规划，但记忆必须有可靠性后验和失败对比。每个 skill 还要绑定员工、部门、工具权限和来源事件。

LEGOMem: Modular Procedural Memory for Multi-agent LLM Systems · AAMAS 2026

类别：D；OfficeBench；full-task memory 分配给 orchestrator，subtask memory 分配给 task agents。

LEGOMem 把成功执行拆成 full-task memory 和 subtask memory，分别服务于任务分解/Agent 选择和子任务工具执行，并比较 vanilla、dynamic retrieval、query rewriting。它与 Morpheus 当前“两 Agent，一个拆步骤、一个执行工具”的结构高度相似，因此只能作为强先例，不能把双 Agent 本身当创新。Morpheus 需要新增的差异是组织权限和员工身份约束，以及 skill 污染导致的内部威胁反事实。

IntentCUA: Learning Intent-level Representations for Skill Abstraction and Multi-Agent Planning · AAMAS 2026

类别：D；Planner、Plan-Optimizer、Critic；shared plan memory；报告 74.83% task success 与 0.91 Step Efficiency Ratio。

IntentCUA 说明原始交互轨迹太低层，必须抽取 intent-level representation 以稳定长程执行。对企业行为模拟，不能从“员工点击了什么”反推全部意图，应该保存“观察到的意图”“组织上允许的意图”“实际动作”三个层次，显式记录计划漂移。

Reinforcement Learning for Self-Improving Agent with Skill Library (SAGE) · ACL 2026

类别：D；Sequential Rollout；skill 在相似任务链中积累；AppWorld；报告 Scenario Goal Completion +8.9%。

SAGE 将前一任务生成的 skill 放入后续任务，并给 skill generation/use 增加 reward。它支持“跨日员工流程复用”的叙事，但也暴露出一个风险：相似任务上的经验跟随会把错误快速扩散。Morpheus 必须测 skill contamination rate、失败复用率和跨员工迁移边界，而不能只报完成率。

How Memory Management Impacts LLM Agents: Experience-Following Behavior · ACL 2026

类别：D/E；研究 memory add/delete、错误传播和 misaligned experience replay。

这篇实证工作直接警告了 Morpheus 的 skill memory：相似输入会诱发相似输出，错误经验会传播，表面正确的经验也可能对新任务有害。它提供了 skill 评测的最低要求：加入/删除操作的因果对照、未来任务作为免费质量标签、错误扩散和过期策略。

4.4 安全和反事实：内部威胁应是同一生成器上的干预

Building a Foundational Guardrail for General Agentic Systems via Synthetic Data · ICLR 2026

类别：C；AuraGen 生成 benign trajectories、注入分类风险、校准难度并用 reward model 过滤；Safiron；Pre-Exec Bench。

它把安全数据生成放到动作执行之前，并将风险类型、难度、分支轨迹和解释纳入数据。对 Morpheus 的启发是：恶意员工轨迹不能只是单独写攻击脚本，而应从同一 benign task 出发，通过 intent、permission、memory 或 information-flow 单一干预生成 counterfactual。评测要同时报告风险检测和正常任务误拒绝。

AgentLAB: Benchmarking LLM Agents against Long-Horizon Attacks · ICML 2026

类别：C；5 类长时攻击、28 个环境、644 个安全测试案例：intent hijacking、tool chaining、task injection、objective drifting、memory poisoning。

AgentLAB 证明单轮安全评测不能覆盖长时攻击。Morpheus 可以借鉴攻击类型，但不能把内部威胁直接等同于它们：企业威胁还需要部门目标、权限审批、内部信息流和员工日程的自然背景。生成器应输出每一步风险的来源，不只输出最终是否攻击成功。

A2ASecBench: A Protocol-Aware Security Benchmark for Agent-to-Agent MAS · ICLR 2026

类别：C；供应链与协议逻辑攻击；travel、healthcare、finance 三类官方 A2A demo；安全–效用联合评测。

A2ASecBench 关注的是 Agent 之间协议、能力发现、任务编排和 artifact exchange 的攻击面。它对 Morpheus 的可迁移点是：跨部门 handoff 本质上也是一种带权限的消息协议。每次 manager → department → employee 的约束传递都应有 schema、发送者、接收者、可见字段和完整性检查。

PropensityBench: Evaluating Latent Safety Risks via an Agentic Approach · ICLR 2026

类别：C；5874 个场景、6648 个 proxy tools、四类高风险领域；在压力、资源稀缺和更高 autonomy 下观察选择。

PropensityBench 的核心不是问模型“能不能完成攻击”，而是给它受控工具后观察“在压力下会选择什么”。内部威胁模拟可以借鉴这一点：在相同企业状态下改变时间压力、绩效激励、资源稀缺或权限诱因，观察员工是否越权、隐藏或转移信息。这样内部威胁是可控的行为倾向评测，而不是 prompt 中写“员工是坏人”。

Causal Detection of Multi-Step LLM Agent Attacks (CausalTrace) · ICML 2026

类别：C；用 Structural Causal Model 表示数据依赖、信任转移和状态使能，通过 do-calculus 询问阻断注入后危害是否仍会发生。

CausalTrace 给出了内部威胁叙事最重要的技术升级：检测器应回答“如果没有这一条权限变化/记忆污染/跨部门转发，结果还会发生吗”，而不是找攻击关键词。Morpheus 的 event log 必须保留 typed edges，支持 benign / insider 对齐重放和因果归因。

Architecture Matters for Multi-Agent Security · ICML 2026

类别：C/E；系统比较角色、拓扑和 memory visibility 对规划拒绝、执行拦截和攻击完成的影响。

这篇工作说明安全性是架构属性。Morpheus 的层级会议、双 Agent handoff 和 employee skill memory 正好是三种可控的安全变量：角色决定谁能下目标，拓扑决定信息如何传播，memory 决定谁能看到过去的行为。论文必须把这三者当作可消融的机制，而不是工程实现细节。

When Benign Inputs Lead to Severe Harms (AutoElicit) · ICML 2026

类别：C；从 benign instructions 出发，基于 CUA execution feedback 迭代扰动，发现长尾 unintended behaviors。

AutoElicit 对内部威胁最有价值的地方是“输入看起来良性，危害来自执行过程”。企业员工也可能从正常邮件、日程或文件任务开始，在权限、记忆和工具反馈的组合下产生严重偏差。因此 benign/insider 对照必须控制任务起点相同，区别只来自可解释干预，而不是人为把恶意目标写进初始指令。

I-EDI: Robust Self-Evolution Agents via Verifiable Counterfactual Simulation · IJCAI 2026

类别：C/D；只接受在数值、上下文等 counterfactual perturbation 后保持依赖图同构的推理轨迹。

I-EDI 把“通过最终答案的轨迹”与“结构稳定的轨迹”分开。Morpheus 需要类似标准：一条员工行为轨迹只有在改变非关键表面因素后仍满足组织依赖、权限和时间约束，才可作为 skill 或 benign reference。对 threat trajectory 则要求干预来源稳定、影响范围可解释。

Integrating Counterfactual Simulations with Language Models for Explaining Multi-Agent Behaviour (AXIS) · AAMAS 2026

类别：C/E；LLM 通过 what-if/remove 反复询问环境模拟器，生成动作解释。

AXIS 不是数据生成 benchmark，但提供了企业轨迹解释方法：在同一环境中删除某个 Agent 动作、修改某个状态，观察其他 Agent 的反应。它可用于把内部威胁报告从“员工执行了可疑动作”提升为“没有该信息流/权限/记忆事件时，该动作不会出现”。

HardSecBench: Benchmarking Security Awareness of LLMs for Hardware Code Generation · IJCAI 2026

类别：C；924 任务、76 CWE；multi-agent synthesis/verification pipeline；每项有 specification、secure reference 和 executable tests。

HardSecBench 的可迁移点是“生成和验证解耦”：一个 Agent 构造测试样例，另一个执行和验证，安全标签必须落到可执行证据。Morpheus 的内部威胁标签也应有 executable evidence，例如越权 API 返回、文件 ACL 改变、邮件外发或跨部门信息流，而不是只看自然语言意图。

4.5 评测数据和专业环境：企业场景需要自己的主 benchmark

REAL: Benchmarking Autonomous Agents on Deterministic Simulations of Real Websites · NeurIPS 2025

类别：B/E；11 个真实网站的确定性副本，112 个任务，programmatic state checks + rubric LLM judgment。

REAL 的方法论直接适用于企业沙箱：使用真实系统结构但在确定性副本中运行，动作任务用程序状态检查，开放式内容用 rubric 评分。OrgTrajBench 应采用 event-sourced deterministic replay，而不是让检测结果依赖在线服务状态。

AgentAuditor: Human-level Safety and Security Evaluation for LLM Agents · NeurIPS 2025

类别：C/E；ASSEBench 2293 条交互记录、15 类风险、29 个场景；Strict/Lenient 双标准。

AgentAuditor 将评测器也做成有经验记忆的 Agent，并区分严格和宽松的风险判定。企业威胁标注可采用同样的双标准：严格标准把潜在越权都计入，宽松标准只计入有可执行后果的事件；报告时不能只给一个含义不清的“攻击率”。

WASP: Benchmarking Web Agent Security Against Prompt Injection Attacks · NeurIPS 2025

类别：C/E；端到端 web agent security；区分攻击部分成功和攻击者目标完全完成。

WASP 提醒我们把“部分泄露”“错误动作”“最终目标完成”分开。内部威胁也应报告信息暴露量、权限影响、任务中断、检测延迟和攻击目标完成，而不能把所有异常压成二元标签。

ResearchEnvBench: Benchmarking Agents on Environment Synthesis · IJCAI 2026

类别：B/E；给定 research repository、documentation 和目标执行环境，要求 Agent 构造可运行环境。

ResearchEnvBench 的价值在于把“环境配置”作为独立能力评测。企业 Agent 轨迹如果不记录工具版本、权限版本、组织状态和初始数据，无法复现。OrgTrajBench 应把环境合成/恢复失败作为单独指标，而不是把所有失败归因给员工策略。

Automatically Benchmarking LLM Code Agents through Agent-driven Annotation and Evaluation · AAMAS 2026

类别：A/C；PRDBench：50 个真实 Python 项目、20 个领域、结构化 PRD、评价标准和 reference implementation。

PRDBench 使用 Agent-driven annotation 和 Agent-as-a-Judge 扩展项目级 benchmark。对 Morpheus 的启发是把企业行为场景写成结构化 PRD：组织状态、任务目的、允许工具、期望后置条件和安全约束；自动 judge 只能作为辅助，硬约束应由程序状态检查。

6. 由文献反推的 Morpheus 研究对象

建议把论文标题和问题收敛为：

OrgTraj-Harness: Organizationally Constrained Agent Trajectory Generation for Enterprise Insider-Threat Simulation

Input: G_org, P_role, H_goal, S_schedule, U_tools, M_skill, I_intervention
Output: τ = {(org_state_t, intent_t, mode_t, handoff_t, tool_event_t, provenance_t)}
Constraint: dependency, authorization, temporal coherence, information-flow, and intervention locality

其中 G_org 是组织图，P_role 是角色和权限，H_goal 是公司—部门—个人的目标层级，S_schedule 是日程和时间压力，U_tools 是有状态工具，M_skill 是带来源的程序性记忆，I_intervention 是 benign/insider 的单一干预。轨迹中的“人–Agent”不再是泛泛叙事，而是 intent → plan → handoff → tool event → state transition 的显式观测。

6.1 三个必须成为算法对象的模块

Organizational Constraint Graph

将层级、部门依赖、角色权限、信息可见性、日程和目标传播写成可检查图。负责人会议的输出应是 constraint packet，而不是一段自然语言会议记录。

必须新增：goal dependency、authority edge、visibility edge、time window、postcondition。

Risk–Complexity Intent Gate

在事件边界判断 login/logout 等简单状态转移，还是邮件、浏览、文件和其他复杂任务；同时估计风险和不确定性，支持 abstain 或 human review。

必须学习/校准 route，而不是只写关键词规则；指标包括调用成本、错误路由和安全误拒绝。

Provenance-Constrained Skill Automaton

skill 是带触发条件、前置/后置条件、授权范围、工具边、来源轨迹、可靠性和污染状态的可执行子图。

复用前做权限/状态检查，复用后记录 uses、failure 和 provenance；不把全文记忆冒充 skill。

6.2 企业轨迹最小 schema

event_id, employee_id, department_id, role, timestamp, schedule_slot
org_state: {manager_goal, department_goal, dependencies, visible_state}
intent: {benign/uncertain/risky, target, pressure, confidence, source}
handoff: {human_planner, tool_agent, request, acceptance, revision}
tool_event: {tool, args_hash, result_state, authorization, side_effect}
skill: {skill_id, trigger, precondition, postcondition, source_event_ids, reliability}
provenance: {parent_events, intervention, verifier, replay_seed}

这个 schema 的意义是让评测可以在轨迹层进行，而不是只比较员工回复文本。每个动作必须能回答：谁在什么组织状态下做了什么、依据是什么、权限是否允许、状态如何改变、下一步是否由人或 Agent 产生、该流程来自哪条历史经验。

7. OrgTrajBench：主 benchmark 应该如何定义

通用 Agent benchmark 可以作为局部 sanity check，但不能作为论文主结果。OrgTrajBench 应围绕企业行为模拟建立四个 split，并与公开企业数据的分布统计对齐。

split输入生成/评测任务关键指标

DailyBehavior个人日程、时间压力、工具状态、历史 skill生成登录、邮件、浏览、文件、日程和等待/重试等长程事件时间间隔/burstiness、任务切换、工具序列、失败恢复、计划–执行偏差、跨日一致性

公开数据只用于行为锚定：CERT Insider Threat Dataset 可校准登录、文件访问和内部威胁事件；LANL cyber data 可校准认证、进程和网络活动；Enron email dataset 可校准通信图和时间模式。它们通常没有完整的员工意图、工具 API 状态或组织会议过程，所以不能直接被描述为 ground-truth employee trajectories。

8. 最小实验阶梯：每一步只回答一个问题

问题对照实验必须看到的证据
Q1 分层规划是否改变结构真实性？全员 meeting、随机部门、head → department固定模型、组织、员工和随机种子，只改变规划拓扑依赖满足率、冲突解释率、干预 locality；若只提升文本相似度，不能当主贡献

9. Research road：文献如何把创新点更新到当前程度

R0

原始想法：四个更真实的模块

层级会议、简单/复杂行为快速判断、两个 Agent 模拟人–Agent 协作、skill 沉淀。判断：直觉合理，但不足以构成 ICML 方法

原因是每个模块在多智能体、Agent memory、computer-use 和 safety 文献中都有相邻先例；如果没有统一的数据对象和可证伪性质，叙事会被审稿人看成工程组合。

R1

ICLR / NeurIPS / IJCAI：把目标改成“数据生产器”

AgentSynth、AutoPlay、TaskCraft、APIGen-MT、GUI-ReWalk 和 WebSTAR 共同说明：任务生成、轨迹采样、执行验证、步骤过滤应该是分层流水线。更新：Morpheus 的产物定义为结构化企业行为轨迹

实现程度：当前仓库已经有层级 planning、行为 router、handoff 和 skill memory 原型；仍缺组织状态执行器、轨迹 verifier 和可复现实验协议。

R2

CVPR / AAMAS：把“真实”改成状态动力学和角色互动

WebGym、REAL、DecompGAIL、Active Markov Games、LLMEvalRec、UrbanMix、BotVerse 和 CogEA 表明，真实性来自环境状态、时间模式、异质角色、互动反馈以及与真实分布的校准。更新：员工不是收到计划后独立调用工具，而是在组织状态中行动

实现程度：代码中已保留事件路由和 handoff 记录；下一步必须把组织图、权限和工具状态写入统一 event log。

R3

ICML / AAMAS / ACL：把 skill 限定为有来源的可执行流程

ProcMEM、MACLA、LEGOMem、IntentCUA、SAGE 和 memory management 工作共同改变了 skill 定义：触发、前置、步骤、终止、可靠性、失败记录和来源都必须可检查。更新：SkillMemory 从“文本记忆”升级为 provenance-constrained skill automaton

实现程度：仓库已有员工隔离、原子写入、触发词、步骤摘要和工具画像；尚缺权限验证、污染检测、可靠性后验和跨员工迁移实验。

R4

ICML / ICLR / IJCAI：把安全改成同一生成器上的反事实干预

AgentLAB、AuraGen、A2ASecBench、PropensityBench、CausalTrace、I-EDI、AXIS 和 HardSecBench 提供了长时风险、协议攻击、风险倾向、因果归因、反事实筛选和执行证据。更新：内部威胁 = benign 企业轨迹上的单一意图/权限/记忆/信息流干预

实现程度：当前日志字段可以承载 stage、decision、skill provenance 和 handoff；尚未实现成对重放、do-intervention、因果 locality 和检测器跨域评测。

R5

最终论文命题：OrgTraj-Harness

把组织约束图、风险–复杂度 gate、显式 handoff 和 skill automaton 统一为一个可替换的轨迹生成器；用 OrgTrajBench 评测真实性、成本、安全和下游内部威胁检测泛化。当前状态：方向成立，方法和实验仍待验证

这一步是能否达到 ICML 2027 门槛的分水岭。没有结构化算法、轨迹级指标、跨组织泛化和安全失败分析，论文仍会退化为 Agent 工程系统。

10. 对 Morpheus 当前代码实现的最小修改建议

现有原型已经围绕 hierarchical_planning.py、hierarchical_meeting.py、behavior_router.py、task.py 和 skill_memory.py 建立了最小 harness。为了不破坏现有流程，后续实现只需要增加可审计字段和可替换接口：

1. 组织状态字段

在既有 meeting response 和 employee plan 旁增加 department dependency、visible state、authority edge、schedule slot；保留全员 meeting 作为 ablation。

2. 路由证据

保留 category、action、confidence、reason，同时记录 route cost、risk、abstain 和 downstream outcome，避免 router 只成为程序分流。

3. skill provenance

在现有 skill JSON 中增加 source_event_ids、pre/postcondition、authorized_tools、reliability、failure_count 和 contamination_state。

4. 反事实重放

增加离线 replay 接口，只在合成身份和沙箱中改变一个干预变量，输出 paired trajectory；不改变默认真实工具执行路径。
